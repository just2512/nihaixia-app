# 全模式红旗门禁入口审计——历史方案归档

> **当前状态：SUPERSEDED / NOT APPLICABLE（2026-11-26）**
>
> 本报告早期将研纪按临床诊断/分诊产品设计红旗 detector、医学审核和全入口强制拦截，属于产品范围偏移。当前产品定位为辅助中医学习，不是医疗诊断软件或临床分诊系统。本文不再作为当前入口审计任务、代码验收标准或发布门槛。

## 当前结论

- 不建设临床红旗 detector、医学风险分类器或临床分诊系统。
- 不要求医学背景人员审核医学词表、阈值、例外或处置文案；不要求医生签字、审核责任人或医学规则版本审批记录。
- 不把自动、问诊、学习、工具、玄学五种模式的模型调用入口改造成临床红旗拦截入口。
- 不要求对 initialPrompt、历史续聊、附件转写/图像描述、工具结果回流建立临床红旗识别矩阵。
- 不因上述 detector、审核、覆盖率、测试或 TRACE 缺失阻断正常学习与既有业务流程。
- 简明急重症求助提示按 `docs/product-positioning-and-boundaries.md` 执行；它是一般性求助提醒，不是检测器、分诊规则或阻断条件。
- 通用输入校验、工具参数校验、权限校验、执行状态校验和跨模式领域隔离仍是有效工程要求，但不得与临床红旗安全门禁混称。

## 历史材料的处理

本文后续保留的旧入口表、旧代码行号、旧 detector 状态、旧测试矩阵和旧 RELEASE BLOCKED 结论，仅用于追溯当时的设计过程。它们不构成当前待办，不得复制到执行清单、CI gate、PR 模板或发布检查表。

历史类 `RedFlagGate` / `RedFlagPreflight` 不代表产品具有临床识别能力。若旧 TRACE 字段因兼容性仍存在，应标记 `NOT_APPLICABLE`，不得执行检测或阻断模型调用。
