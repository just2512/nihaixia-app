# 全模式模型入口与一般性求助提醒边界

> **当前状态：NOT_APPLICABLE（不属于当前产品功能或发布门槛）**  
> 最后校准：2026-11-26。本文替代此前将本项目按临床红旗检测/分诊系统设计的审计内容。

## 1. 产品定位

研纪是中医学习辅助工具，不是医疗诊断软件、临床分诊系统或医疗决策系统。产品支持中医知识学习、经典与医案分析、辨病辨证过程学习，以及对 App 现有确定性规则结果的解释。真实业务计算和规则结论由 App 既有代码执行；AI 不得伪造、替换或覆盖这些结果。

因此，当前产品**不建设临床红旗 detector、医学风险分类器或临床分诊门禁**。以下事项均不属于当前工程要求，也不得作为模型调用、普通路由、工具执行或版本发布的前置条件：

- 医学红旗词表、医学阈值、临床风险等级及其覆盖率指标；
- 由医生或医学背景人员审核词表、语义规则、阈值、急救/处置文案；
- 医学审核人、审核版本、审核日期、责任审批或临床 detector 版本记录；
- 对自动、问诊、学习、工具、玄学五种模式实施临床红旗全入口拦截；
- 因 detector 缺失、未审核、覆盖不足或无法评估而产生的 REVIEW_REQUIRED、RELEASE BLOCKED 或同等发布阻断。

不得把上述事项继续列为 MISSING、PARTIAL、待办或外部交付依赖。

## 2. 保留的一般性求助提醒

当对话出现明显急重症描述时，可以显示固定、简明的一般性求助提醒，例如建议立即拨打当地急救电话或前往急诊。该提醒：

- 只用于提示及时寻求现实世界的专业帮助；
- 不判断病情、不评估风险等级、不预测病程；
- 不提供急救操作、个体化治疗或医疗处置指令；
- 不要求先运行 detector，也不阻断正常学习、知识解释或 App 既有确定性业务。

提醒文案属于产品通用提示，不属于医学阈值或经临床审核的处置规则。不得扩展为症状分类器或伪装成临床评估结论。

## 3. 仍然必须执行的通用工程约束

下列约束与临床红旗检测无关，仍按既有架构执行：

- 输入结构、附件格式、长度、路径和数据完整性校验；
- 模式职责、工具白名单、参数和权限校验；
- 确定性业务执行前的必需参数校验，以及执行结果、来源和状态验证；
- 历史会话恢复时区分用户原始内容、助手回复、历史记录和当前输入，不把助手生成内容伪装成用户自述；
- 对模型输出进行协议校验；执行状态未知时不得伪称成功或自动重放；
- 对不明确的任务参数或业务意图进行普通交互澄清。

这些检查是输入/业务契约，不得命名为临床红旗门禁，也不得要求医疗人员审核。

## 4. TRACE 与兼容字段

旧 TRACE schema 中如仍保留 `preflight`、`redFlag` 或相似字段，仅为历史数据兼容。当前普通学习和助手流程应记录 `NOT_APPLICABLE`（或由当前 TRACE 合约省略该阶段）；该状态不表示 detector 已运行、医学风险已排除或获得医疗安全认证。

不得为了填满旧字段而接入临床 detector，不得把 NOT_APPLICABLE 改写成 CLEAR，也不得把旧字段状态纳入发布阻断判断。

## 5. 当前测试边界

测试应验证真实产品行为：不同模式能够正常路由；附件、历史续聊、initialPrompt 和工具结果遵循各自数据/参数契约；通用校验失败时给出正确反馈；一般性求助提醒在既定场景下可见且不会变成临床判断。

不再建立以下测试矩阵：红旗正向/否定/他人/既往史/知识性提问/假设/引用/时间的临床 detector 语义覆盖；医学阈值边界；审核版本；detector fail-closed；全入口临床拦截顺序。此类测试属于不在本项目范围内的临床软件验证。
