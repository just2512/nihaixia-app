# 红旗 preflight 历史策略归档与当前产品边界

> **当前状态：SUPERSEDED / NOT APPLICABLE（2026-11-26）**
>
> 研纪是中医学习辅助工具，不是医疗诊断软件、临床分诊系统或临床风险管理产品。临床 RedFlag detector、医学词表/阈值审核、医生签字、全模式临床红旗门禁及其发布阻塞条件均不属于当前产品范围。本文件不再定义生产模型调用门槛。

## 当前有效要求

1. 保留产品定位文件规定的简明免责声明和一般性急重症求助提示。
2. 该提示是面向用户的一般提醒，不是对用户进行医学风险识别、风险分级或临床分诊。
3. 不要求建立医学红旗词表、阈值、临床 detector、规则审批、医学背景人员审核或审核版本记录。
4. 不得因缺少 detector、医学审核、红旗测试矩阵或相关 TRACE 而阻断正常的中医知识学习、问诊学习、工具、玄学、图片/语音理解或模型调用。
5. 通用输入格式、参数、权限、工具执行状态、数据完整性和模型调用可靠性校验继续有效；这些校验不得包装成临床红旗检测。
6. 不得把模型 prompt 当作临床安全门禁，也不得宣称本项目具有临床急症识别或分诊能力。

## 历史实现说明

`lib/services/red_flag_gate.dart`、`lib/services/red_flag_preflight.dart` 及对应测试曾用于探索临床红旗 detector 的 fail-closed 策略。相关字段和状态（如 `ruleSetReviewed`、`detectorCoverageComplete`、`REVIEW_REQUIRED`、`BLOCK_URGENT`）属于历史临床方案，不是当前业务契约。不得由这些历史类型推导生产流程必须等待医学审核或默认阻断。

若旧 TRACE schema 为兼容性保留 `redFlag` / `preflight` 阶段，只能记为 `NOT_APPLICABLE`，不得要求收集 detector 证据，也不得作为模型调用 gate。

## 变更约束

未来只有在用户明确改变产品定位、单独批准临床产品范围后，才可重新讨论临床检测器或临床分诊能力；不得在本学习辅助工具的普通改造中自行恢复这些要求。
