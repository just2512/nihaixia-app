# 临床红旗 Preflight：当前产品不适用

> **状态：NOT_APPLICABLE（已退出当前产品范围）**  
> 最后校准：2026-11-26。

## 1. 结论

研纪是中医学习辅助工具，不是医疗诊断、临床分诊或医疗决策软件。当前产品不实施临床红旗检测器，也不以医学审核、临床覆盖率或医生审批作为助手能力的准入要求。

因此，本文件不再定义可投入生产的 RedFlag detector、Preflight 状态机或 fail-closed 临床门禁。旧版 `RedFlagGate` / `RedFlagPreflight` / Native RedFlag boundary 设计不得被视为当前生产安全能力，也不得继续要求补充医学词表、阈值、例外、处置文案、审核签字或版本记录。

## 2. 不适用的旧要求

以下旧设计全部标记为 `SUPERSEDED / NOT IN SCOPE`：

- 以医学审核完成为前提生成或启用 detector 规则集；
- 对本人、他人、知识性问题、假设句、引用、既往史、否定表达和时间范围建立临床红旗分类状态机；
- 对图片、语音、转写、历史恢复、工具结果和 initialPrompt 建立临床红旗全入口覆盖证明；
- detector 缺失、超时、来源不完整、规则未审核时阻断所有或部分模型调用；
- 将 `REVIEW_REQUIRED`、`BLOCK_URGENT` 或类似结果用作学习功能的路由/发布门槛；
- 保存医学审核人员、规则版本、阈值、处置文案及责任审批记录。

不得把这些项目重新登记为 MISSING、PARTIAL、外部依赖或 RELEASE BLOCKED。

## 3. 保留的产品边界

1. App 既有确定性规则负责实际辨病辨证、计算和工具执行；AI 负责理解、澄清、归纳和解释经验证的业务结果。
2. AI 不得独立伪造 App 尚未执行的规则结果，不得覆盖规则结论，不得虚构知识库来源。
3. 对信息不足或工具参数不完整的普通业务请求，按相应业务契约澄清；这不是临床红旗评估。
4. 可以显示固定、简明的一般性急重症求助提醒。它只建议及时寻求现实世界的专业帮助，不进行临床判断，不提供急救或个体化处置方案，也不阻断正常学习流程。
5. 继续执行通用输入校验、附件校验、权限与参数校验、结果协议校验、会话归属和执行状态校验。

## 4. 兼容与迁移

如代码或旧 TRACE schema 仍存在 `redFlag` / `preflight` 字段，只允许作为过渡兼容项，状态使用 `NOT_APPLICABLE`；不得调用临床 detector、不得改变普通业务路由，也不得将其解释为医疗风险已评估或安全 PASS。

代码清理应移除未启用的临床 gate 注入、医学审核元数据、Native 临床边界和仅验证医学审核门槛的测试。不得删除通用输入/参数校验、App 确定性规则、一般性求助提醒、会话恢复与 TRACE 的其他阶段。

## 5. 验收准则

- 普通学习、问诊学习、工具和玄学模式不依赖临床 detector 即可按既有规则工作；
- initialPrompt、历史续聊、附件转写/图像描述和工具结果回流按各自业务数据契约处理，不携带临床 detector 准入参数；
- 急重症一般性求助提醒保留，但不生成临床风险等级，不阻断普通学习流程；
- 通用输入、参数、权限、规则执行状态和模型结果校验继续有效；
- 自动化测试不再要求医学审核、临床阈值或红旗语义 detector 覆盖。

旧 RedFlag Preflight 不存在“待完成后才能发布”的状态；当前状态固定为 `NOT_APPLICABLE`。
