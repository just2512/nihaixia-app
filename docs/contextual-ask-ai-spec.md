# 情境问 AI（Contextual Ask AI）功能协议与接入标准

> 状态：功能协议（规范性文件）
> 适用范围：`just2512/nihaixia-app` 中的经典阅读、知识库详情、方剂/本草/医案及工具结果解释页面。
> 本文件定义产品行为、上下文契约和页面接入标准；具体实施进度、分支、PR、测试与设备证据只记录在 [AI 改造执行台账](ai-modernization-execution-ledger.md)。
> 本协议不代表相关功能已实现。若与全局 AI 安全、产品定位或工程约束冲突，以 [AI 能力审计与改造约束](ai-capability-audit.md) 和产品定位文件为准。

## 1. 目标与非目标

### 1.1 产品目标

情境问 AI 是贯穿阅读、学习和工具使用过程的上下文能力。用户不必离开当前页面、重新描述所处内容或手工复制结果，即可针对当前选中文字、条文、知识条目、工具结果或字段发起提问。

AI 应表现为随当前任务出现的伴读助教/结果讲解入口，而不是要求用户先进入一个空白聊天框，再自行组织上下文。

核心场景：

- 阅读经典、方剂、本草、医案或其他知识资料时，选中不理解的字、词、句或段落，直接询问其含义、语境、相关概念和出处。
- 使用排盘、历法、辨证或其他工具后，针对当前真实结果整体提问，要求解释结构、字段、规则依据及相互关系。
- 在结果页面对具体字段发问，后续可扩展到图表、局部结构和跨字段关系。

### 1.2 非目标

- 不新建独立 AI 聊天产品或第二套会话/消息存储。
- 不复制或重写现有模型执行、助手模式路由、检索、安全前置检查和结果解释体系。
- 不让模型重新计算排盘、辨证、剂量或其他确定性业务结果。
- 不把未经验证的模型记忆当作本地知识库出处。
- 不在第一批一次性改造所有阅读页面、所有工具或所有字段。
- 不以自动化测试替代 Find N2 真机验收，也不将未执行的测试标记为通过。

## 2. 用户交互协议

### 2.1 阅读内容划词提问

1. 用户在可选择的正文中选中一段文字。
2. 系统在原生选择菜单或项目自定义菜单中提供“问 AI”操作。
3. 用户触发后，当前页面保持可恢复状态，打开情境助手面板。
4. 面板展示本次提问所依据的选中文字及必要出处；用户可以直接提问，也可以使用上下文相关的快捷追问。
5. AI 回答应围绕原文语境解释，不把孤立选词误当作完整问题；可在确有本地资料依据时关联其他条文或知识条目。

第一批仅接入一个《伤寒论》条文详情页作为样板。不得因为 Markdown 正文已支持文字选择，就推断“问 AI”菜单和来源定位已经完成。

### 2.2 工具结果整体提问

1. 工具完成实际计算或业务执行后，在结果区域提供“问 AI”入口。
2. 点击后将当前结果的稳定引用和经过校验的结构化数据交给上下文解析层。
3. AI 解释当前结果，不得自行重算、补造缺失字段或覆盖 App 结果。
4. 用户继续追问时，仍绑定最初建立会话时的结果快照。
5. 结果重新计算后，旧会话仍指向旧快照；用户明确选择“基于新结果开始解读”时，才创建新锚点/新会话。

第一批工具样板选择一个已有真实结果结构和解释链路的排盘结果页。不得用人工拼装的假结果替代真实 App 输出。

### 2.3 字段级提问

字段级入口可在整体结果问 AI 验收后扩展。字段提问必须包含：

- 稳定的字段路径（如 `fieldPath`），不能只传显示名称。
- 所属结果快照 ID 和字段所属模块。
- 字段值、单位、数据口径及可用的规则/来源说明。
- 字段缺失或无法定位时的明确状态。

字段入口不能绕过整体结果的来源、权限和安全约束。

## 3. 统一上下文契约

### 3.1 分层模型

上下文引用、真实数据解析和提示词构建必须分离，禁止把所有逻辑塞入一个同时负责存储、查找和生成 prompt 的大对象。

建议职责如下：

| 层 | 建议类型 | 职责 | 不负责 |
|---|---|---|---|
| 上下文引用 | `AiContextRef` | 表达来源类型、模块、稳定锚点、版本、选中文字/字段路径 | 不携带未经验证的完整业务事实，不生成 prompt |
| 上下文解析 | `AiContextResolver` | 根据引用从本地资料或结果存储解析真实内容，校验权限、归属和版本 | 不调用模型，不猜测缺失字段 |
| 提示词构建 | `AiContextPromptBuilder` | 根据解析结果、助手模式、用户问题和预算构建模型上下文 | 不负责数据检索或业务计算 |
| 面板呈现 | 情境助手面板 | 展示来源摘要、提问输入、回答与追问 | 不建立第二套模型/会话执行链路 |

类型名称可根据项目现有命名规范调整，但职责边界必须保持。

### 3.2 引用结构

建议的最小引用字段：

| 字段 | 含义 | 要求 |
|---|---|---|
| `sourceType` / `kind` | classic / formula / herb / case / toolResult / field 等来源类型 | 必须是受控枚举 |
| `moduleId` | 所属功能模块 | 稳定标识 |
| `anchorId` | 条文、知识条目或结果的稳定 ID | 不得用屏幕坐标或显示文本代替 |
| `anchorVersion` | 内容或结果版本 | 用于发现内容更新/快照变化 |
| `selectedText` | 用户选中的原文 | 划词场景使用；保留原始文本 |
| `fieldPath` | 结构化结果字段路径 | 字段提问场景使用 |
| `sourceReference` | 可解析的本地来源引用 | 必须可回到真实条目 |
| `defaultQuestion` | 可选的建议问题 | 仅作输入建议，不自动替用户提交 |

引用对象只描述“要解析什么”，不能把未校验的 `resultSummary` 或任意文本直接视为权威事实。

### 3.3 上下文解析结果

Resolver 应返回明确的解析状态与来源信息。至少区分：

- `RESOLVED`：锚点、版本和所需内容均已验证。
- `MISSING`：本地资料、字段或来源确实缺失/未检索到。
- `UNKNOWN`：无法确认锚点归属、版本、权限或结果状态。
- `STALE`：引用所指内容已变化，或当前版本与引用版本不一致。
- `DENIED`：用户未授权访问该上下文，或不满足隐私/权限要求。

不得将 MISSING、UNKNOWN、STALE 或 DENIED 自动降级为“让模型凭记忆回答”。

## 4. 阅读选择与出处定位标准

### 4.1 稳定来源锚点

- 每个可提问阅读单元必须拥有稳定的 `passageId` 或等价 ID，并关联书籍、章节、条文/段落 ID 和本地来源 ID。
- 选择事件必须由承载该文本的阅读单元提供来源身份；不能在整个页面中事后用选中文字反查来源。
- 不得使用 `fullText.indexOf(selectedText)` 作为唯一定位方式：相同词句可能重复出现，跨段落选择可能落在错误来源，注释/标题也可能造成错配。
- 无法唯一确认所选内容属于哪个条文或段落时，来源状态为 `UNKNOWN`，禁止猜测。
- 阅读模块 ID 与经典索引 source key 不要求字面相同，但必须由同一处受控白名单提供双向映射；搜索入口、助手回答的来源引用回链和知识库打开入口必须复用该映射，不得各自维护互不一致的 source switch。
- 情境阅读产生的 `sourceId` 必须能按允许的模块别名精确反查到原始索引条目和 asset；反向打开后继续使用同一 canonical module / asset anchor。只允许显式登记的别名，不得按标题、关键词或模糊检索兜底；未知 source、缺失 asset 或索引无对应条目时返回 `MISSING` / `UNKNOWN` 并停止跳转。
- asset 型阅读锚点必须同时校验 moduleId 与其专属本地 asset 目录前缀（并限定为受支持的 Markdown 资源）；来源前缀错配、空路径、路径穿越或未知模块一律返回 `MISSING` / `UNKNOWN`，不得仅凭字符串拼接生成 passageId。伤寒条文的特殊编号映射只允许在统一锚点构造器中声明一次。
- 古籍章节不属于经典讲稿 asset 索引的同一来源类型；只有取得并校验独立原始行号映射后，才可启用其段落级情境入口。缺少映射时保持普通阅读，不得伪造 passage anchor。
- 同一来源经搜索、知识库、实体反向索引或助手引用等不同入口打开时，应归一到同一 module、asset 和 passage 规则；入口数量增加不得生成重复或互相冲突的来源身份。
- 第一批只支持一个独立条文块内的选择；跨条文、跨章节和混合注释选择暂不作为首批验收范围。

### 4.2 Flutter 选择实现

- 优先复用当前阅读组件已有的文本选择能力；先核对实际组件和 Flutter 版本，不重复实现已经存在的能力。
- 可评估统一的 `SelectionArea` 与自定义 `contextMenuBuilder`，在菜单中增加“问 AI”操作。
- 不要求每个段落嵌套独立 `SelectionArea`；阅读容器应统一管理选择交互，具体 passage 的身份由文本块/渲染节点携带。
- 对纯正文讲稿可启用段落级 passage：由阅读容器集中管理每个可选择文本节点，稳定锚点绑定本地 asset sourceId 与原始 Markdown 的起止行；跨段落选择必须不可用或 fail-closed。标题、列表、引用元数据、表格、代码、图片和 HTML 不得提供情境入口。
- 若使用 `Markdown`、自定义 span 或富文本渲染，必须验证选择结果与来源节点的映射。不能证明来源映射正确时，不启用问 AI 操作。
- 选择菜单必须保留复制、全选等既有系统能力，不得因增加“问 AI”破坏平台默认行为。

### 4.3 选择上下文

向 Resolver 传递：

- 选中文字；
- 唯一 passage/anchor ID；
- 当前条文/段落的完整正文或可解析引用；
- 书籍、章节、条文标题等已验证元数据；
- 本地 sourceId 与可打开的详情定位；
- 用户当前问题（若已输入）。

周边上下文只能从同一来源的已验证相邻段落解析，不得无边界拼接整本书。

## 5. 工具结果、快照与版本一致性

### 5.1 真实结果原则

- 结果必须来自 App 实际执行的确定性引擎/规则或已验证业务能力。
- AI 接收的是结果引用和经校验的结构化快照；不从用户界面截图、展示文案或模型记忆反向推算业务数据。
- 结果至少应能关联能力/工具 ID、输入摘要、结构化结果、单位/口径、规则版本、source IDs、缺失字段和执行状态。
- 执行状态为 `UNKNOWN`、`FAILED` 或未完成时，不得把结果作为已成功计算的事实交给模型解释。

### 5.2 快照身份

- 每次实际计算结果必须有稳定的 `resultId` 或等价快照标识。
- 如需内容寻址快照，可基于规范化输入、规则版本和规范化结果内容生成 SHA-256；时间戳不能单独充当内容身份。
- 快照 ID 必须绑定实际输入、规则版本和结果内容，避免只因时间不同就生成不同的内容身份，或因输入变化而复用旧快照。
- 若项目已有稳定结果 ID 和版本字段，优先复用；不为形式统一新增重复存储。

### 5.3 重算与旧会话

- 已创建会话的锚点不可静默改写。
- 工具重新计算后，旧会话继续引用旧 `resultId`；后续追问仍解析旧快照。
- 新结果应建立新锚点；用户选择“基于新结果开始解读”时创建新会话，明确显示新结果摘要。
- 若旧快照因清理或迁移而不可用，显示明确的 `MISSING` / `UNKNOWN` 状态，不得自动切换到最新结果。

## 6. 助手模式、执行链路与安全边界

### 6.1 复用现有助手体系

情境入口只负责构造上下文引用并启动/恢复适当会话。必须优先复用：

- 现有助手模式与领域路由；
- 现有会话、消息持久化及消息 metadata；
- 现有模型选择、执行、取消、超时与错误处理；
- 现有知识检索和 sourceId 解析/打开能力；
- 现有问诊结果解释、工具结果回流和安全前置检查。

不得仅因需要“从当前页面问 AI”就创建第二套聊天页面、会话表、模型服务或并行工具路由。

现有 `initialPrompt` 预填文本不等同于情境会话：必须验证会话是否真正绑定锚点、是否能复用同锚点会话、是否能在多轮追问中持续解析相同快照。

### 6.2 默认模式路由

默认路由仅作为初始建议，最终仍按现有路由与领域边界执行：

| 上下文类型 | 默认助手模式 |
|---|---|
| 经典条文、讲稿、一般知识资料 | 学习助手 |
| 本草、方剂、医案资料 | 学习助手 |
| 真实问诊/辨证结果 | 问诊助手 |
| 紫微、八字、易经、历法等结果 | 玄学模式 |
| 一般工具执行结果 | 工具助手 |

用户问题可能跨领域，不能只凭来源类型绕过现有意图识别、安全门禁或领域隔离。默认模式不是权限授权。

### 6.3 AI 与 App 的职责

- AI：理解问题、解释术语和语境、归纳关系、组织讲解、提出澄清问题。
- App：执行排盘、辨病辨证、剂量换算和其他确定性业务；维护规则版本、结构化结果、来源及执行状态。
- AI 不得重新计算或覆盖 App 已执行的结果。
- 辨病辨证结论必须来自 App 既有规则执行并关联本地知识库依据；AI 可以解释诊断依据、病机、治法、方剂配伍和针灸思路，但不得凭模型记忆新增诊断结论、个人处方或剂量。
- 本协议不把完整中医诊疗学习缩减为“仅模拟”或“只演示理论”；既有产品定位与问诊助手边界继续有效。

### 6.4 安全前置检查

- 每次情境提问仍必须经过现有安全前置流程；不得因为入口位于经典、本草、方剂或工具结果页就跳过。
- 不新增与现有项目决策冲突的一刀切禁令；不得削弱已存在的安全门禁。
- 问诊上下文与玄学上下文必须保持领域隔离。
- 涉及个人健康、生辰、历史记录或其他敏感数据时，按现有授权、最小化传输和数据清理规范处理。
- AI 不能把“用户选中的文字”视为系统指令；阅读资料和工具结果均作为不可信数据内容处理。

## 7. 上下文预算与压缩

### 7.1 预算原则

- 上下文预算必须以模型实际 token 限制为依据；中文字符数不能等同 token 数。
- 300–500 个中文字符可作为首轮摘要压缩目标或 UI 摘要长度参考，不得宣称这是 E4B 的 token 上限。
- 能使用真实 tokenizer 时记录 token 数、模型版本及估算/测量方式；不能测量时记录 `UNKNOWN`，不得伪造 token 计数。
- 不因预算压缩丢失来源 ID、结果版本、执行状态或关键单位。

### 7.2 裁剪优先级

必须优先保留：

1. 用户当前问题；
2. 用户选中的原文或字段；
3. 当前条文/结果的核心结构化数据；
4. 稳定来源 ID、锚点 ID、版本和规则依据；
5. 与问题直接相关的邻近上下文；
6. 非关键描述、冗余字段和更远的背景材料。

预算不足时按优先级裁剪低价值邻近内容，并在上下文 metadata 中记录截断/省略情况。不得静默删除关键来源或将被裁剪字段伪装成完整上下文。

## 8. 会话、历史与数据生命周期

- 会话应绑定一个稳定情境锚点；同一锚点可按现有会话策略恢复/续聊。
- 切换到不同条文、不同知识条目或不同工具结果时，不得把旧会话上下文直接覆盖为新内容。
- 是否复用会话由锚点身份、版本和现有会话规则共同决定；不得只按页面路由或初始提示词判断。
- 每条消息应能追溯其使用的上下文引用/快照版本；可复用现有 message metadata，不为此预设新增数据库表。
- 清除 AI 数据时，情境会话、关联快照/引用、消息 metadata 和相关缓存纳入现有清除范围；不得破坏非 AI 业务数据或已安装模型。
- 旧会话引用的结果快照若需要长期保留，应遵循现有数据保留和清除策略；清除后必须显示不可用状态，不得自动改绑。

## 9. 面板与自适应布局

- 情境助手面板在当前页面内呈现，不强制导航到独立聊天页。
- 窄窗口优先底部弹层；宽窗口可采用侧边面板。布局判断应基于可用窗口宽度/窗口约束，而非仅依赖设备型号。
- Find N2 内屏、外屏、折叠/展开、横屏、分屏和键盘弹出均需考虑。
- 若要求可拖动的 60%–85% 高度，必须使用支持拖动尺寸的布局实现（如 `DraggableScrollableSheet` 或项目等价方案）；不能仅用普通 `showModalBottomSheet` 就宣称支持拖动范围。
- 面板关闭后应保留原页面滚动位置和选择状态（在平台允许范围内）；打开/关闭不能触发工具重算或改变结果快照。
- 无障碍语义、键盘焦点、返回键和选择菜单行为不得退化。

## 10. 引用与回答呈现

- 本地知识库引用必须使用真实、可解析的 `sourceId`，并提供回到原条目/章节/记录的入口。
- AI 生成的相关条目建议必须先经本地检索/解析验证，不能让模型自行拼造书名、条文号、sourceId 或可点击链接。
- 回答中应区分：知识库原文、App 规则/计算结果、AI 解释和用户提供内容。
- 缺失字段标 `MISSING`；来源/归属/版本无法确认标 `UNKNOWN`；过期引用标 `STALE`。
- 不得用无来源的模型记忆填补本地知识库缺项。

## 11. 分阶段接入计划

### Phase 0：协议与现状核验

- 固化本协议。
- 复核当前阅读选择实现、Markdown/富文本来源映射、助手会话 metadata、结果快照持久化能力和现有结果解释链路。
- 记录实际代码路径、可复用组件和缺口；不先新增架构。

### Phase 1：单条文划词问 AI 样板

- 选择一个《伤寒论》条文详情页。
- 确保选择范围唯一映射到 passageId/sourceId。
- 在选择菜单增加“问 AI”入口。
- 复用现有学习助手会话和模型执行链路。
- 验证原文语境、来源回链、多轮追问、关闭面板后阅读状态保留。
- 第一批不扩展为全库所有页面。

### Phase 2：单个工具结果整体问 AI 样板

- 选择一个已有稳定结构化结果和现有解释函数的排盘结果页。
- 提供整体“问 AI”入口。
- 绑定真实输入、规则版本、resultId/snapshotId、结构化输出和来源。
- 验证模型只解释实际结果，不重算、不补造。
- 重新计算后验证旧会话仍引用旧快照；显式基于新结果开始时创建新会话。

### Phase 3：扩展覆盖面

Phase 1/2 的“样板通过”拆分为云端工程门禁与最终设备门禁，避免将本地设备依赖误作云端开发的串行阻塞：

- **云端实施准入**：对应样板的稳定来源/快照契约、关键负向测试、真实调用链自动化、Find N2 窗口宽度布局自动化均已通过；相关 PR 最新 head 的 Flutter regression 与 Android arm64 CI 均为 SUCCESS。SKIPPED、CANCELLED、旧 SHA 的结果均不计 PASS。
- **Phase 3 云端工作**：达到上述云端门禁后，可继续按小批量独立分支实施本草、方剂、内经、医案等阅读入口，其他排盘/历法/辨证工具入口，以及字段级/图表局部/跨字段提问；每个切片必须独立定义页面、上下文契约、文件所有权、负向测试、来源回链和回滚方案。不得一次性全量改造。
- **最终设备门禁**：Find N2 外屏/内屏/半折叠/分屏/键盘交互，以及本地 E4B 多轮问答、Native 状态和历史恢复 TRACE，集中留到云端计划完成后的最终本地验收。云端 CI 和模拟布局不能替代这些证据；未完成时，受影响工作流只能记为 PARTIAL/UNKNOWN，不得宣称端到端 PASS。
- 设备门禁不阻止云端继续修复协议、实现、测试、文档和 CI；但任何实测暴露的设备专属缺陷仍须修复后才能完成最终验收。

每一类扩展仍须独立列出页面、上下文契约、文件所有权和验收项，不得一次性全量改造。

## 12. 自动化验收标准

### 12.1 划词场景

至少验证：

- 选中单条文内连续文本，菜单出现“问 AI”；
- 相同词句在同页多次出现时，仍解析到用户实际选择的 passageId；
- 选择菜单复制/全选行为保持；
- 跨条文或来源不明确的选择被拒绝或标记 UNKNOWN，不错配来源；
- 提问上下文包含选中文字、完整条文引用、稳定 sourceId；
- 回答引用可打开正确的本地知识条目；
- 多轮追问继续绑定同一条文锚点；
- 面板关闭/重开不丢失页面滚动位置或错误切换来源。

### 12.2 工具结果场景

至少验证：

- “问 AI”入口只在实际成功结果可用时启用；
- 上下文中的输入、结果、单位、规则版本、source IDs 与页面当前结果一致；
- 失败/未知/不完整结果不会被当作成功事实发送；
- 模型解释不会修改、重算或覆盖原始结果；
- 重新计算后旧会话仍绑定旧 resultId；
- 明确选择新结果解读后才建立新锚点/会话；
- 旧快照缺失时显示 MISSING/UNKNOWN，不静默切换最新结果。

### 12.3 共通场景

- 模式路由正确，且不能绕过现有安全前置检查和领域隔离。
- 同锚点会话复用规则可测试；切换锚点不会串线。
- 消息 metadata 能追溯实际上下文版本。
- token 预算真实测量或明确 UNKNOWN；截断不会移除关键来源/状态。
- 清除 AI 数据后，情境会话及关联缓存按既有策略清除，非 AI 数据保留。
- Find N2 外屏/内屏布局分别有自动化布局覆盖；真机验收单独记录 TRACE。
- 新增测试只覆盖本协议定义的真实调用链和边界，不为追求数量扩张无关测试。


### 12.4 经典阅读来源双向映射

经典阅读的 reader module ID 与检索索引 source key 可以不同，但正向入口和助手引用回链必须共用明确的双向白名单：

- 正向入口只能由受控 source key / reader module 映射生成 canonical anchor；模块 ID 与索引 source key 不要求字面相同，但映射必须显式登记并有测试。
- 助手引用回链必须按稳定 source ID 精确反查同一条本地资料。asset-backed 阅读仅接受 manifest/白名单中的完整 asset 路径；古籍章节仅接受 book ID、chapter index 与独立原始 TXT 行号映射。
- 不得按标题、关键词、相似度、文件名片段或 indexOf 兜底定位；未知、歧义、缺少来源映射均返回 MISSING / UNKNOWN 并拒绝跳转。
- reader module ID、检索 source key、ContextRef.sourceId、anchorId 的转换必须集中维护，不能由搜索页、详情页和助手页各自拼接。
- 自动化需覆盖正向入口、助手引用回链、重复标题、未知 ID、篡改 asset、额外尾缀、模块/source key 不同、古籍行号缺失等正负向场景。

## 13. 风险、取舍与回滚

| 风险 | 影响 | 控制与回滚 |
|---|---|---|
| 选中文字映射到错误条文 | 错误出处和错误解释 | 强制稳定 passageId；不能唯一定位时禁用问 AI；回滚选择菜单接入 |
| 旧会话绑定到新结果 | 多轮解释事实漂移 | 会话锚点不可变；旧 resultId 保留；回滚新入口而不迁移旧会话 |
| 重复建设助手链路 | 维护成本、行为分叉 | 复用现有会话/路由/执行；若无法复用先提交证据和方案评审 |
| 上下文过长或压缩错误 | 模型忽略重点或丢失来源 | tokenizer 测量/UNKNOWN；按优先级裁剪；保留来源和版本 |
| 面板影响折叠布局 | 溢出、键盘遮挡、状态丢失 | 基于窗口约束适配；自动化覆盖 + Find N2 实测；可独立关闭入口回滚 |
| 结果/个人信息过度传输 | 隐私和数据保留风险 | 最小化上下文、复用授权和清除机制；不把敏感原文写入公共 CI 日志 |

回滚优先按页面入口/组件开关撤回，不删除既有会话、知识数据或工具结果；不得为回滚而破坏已有助手功能。

## 14. 实施交付记录要求

每个实施切片在执行台账中登记：

- Task ID、目标页面/场景、当前 master base SHA；
- 独立分支名、文件所有权、head SHA；
- 实际变更文件和源码定位；
- 针对性测试名称、命令和真实结果；
- format/analyze/编译结果；
- CI workflow、run ID、head SHA、最终结论；
- Find N2 设备、Android 版本、App SHA、模型版本、backend、场景 TRACE；
- 未完成条件、风险、回滚方法和下一项动作。

状态只允许使用 `NOT_STARTED / IN_PROGRESS / PASS / PARTIAL / FAIL / BLOCKED / UNKNOWN`。计划、代码存在、模拟输出和模型自述都不能单独作为 PASS 证据。

## 附录 A：建议的接口职责草图（非强制类名）

以下为职责示意，不要求按名称原样实现：

- `AiContextRef`：稳定上下文引用。
- `AiContextResolver`：解析并校验本地来源、结果快照、权限和版本。
- `AiContextPromptBuilder`：按模式和 token 预算构建上下文。
- `ContextualSelectableBlock`：将选择事件绑定到唯一 passageId/sourceId，并触发问 AI。
- `AskAiResultButton`：对真实工具结果建立情境会话入口。
- `AskAiFieldTrigger`：对字段路径建立情境会话入口。
- `ContextualAiPresenter`：根据窗口约束选择底部弹层或侧栏。
- `ContextualAiSessionCoordinator`：复用现有会话存储和模型执行流程，维护不可变锚点。

最终实现应优先适配现有架构。只有当现有结构确实无法满足本协议且有代码证据时，才新增最小必要抽象。
