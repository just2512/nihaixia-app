## 安装到 OPPO Find N2

先安装本项目生成的 Debug APK，并将模型文件下载到手机可访问的位置（例如“下载”目录）。打开应用「问诊」页，点右上角本地 AI 入口：

1. 点击「选择并导入模型文件」。
2. 在 Android 系统文件选择器中找到 `gemma-4-E4B-it.litertlm`。
3. 等待应用完成本地复制、文件大小和 SHA-256 校验。3.66GB 文件导入期间请保持应用在前台，并确保设备有足够剩余空间。
4. 状态显示文件已安装后，点击「加载本地模型」。

应用只读取用户选择的 URI，不主动请求模型下载服务，也不会上传模型文件；若用户选择云盘类文档提供方，该提供方可能自行联网读取文件。离线验收必须选择设备本地存储中的模型文件。模型不会打包进 APK。导入使用临时文件；校验通过后才替换正式文件，导入失败会保留原文件。

### 可选：通过 ADB 安装（开发者备用方式）

如需使用 USB 调试，先在电脑核对文件 SHA-256：

```powershell
Get-FileHash .\gemma-4-E4B-it.litertlm -Algorithm SHA256
adb devices
```

再复制到应用私有目录：

```powershell
adb push .\gemma-4-E4B-it.litertlm /data/local/tmp/gemma-4-E4B-it.litertlm
adb shell run-as com.nihaisha.nihaisha_app mkdir -p files/ai_models
adb shell run-as com.nihaisha.nihaisha_app cp /data/local/tmp/gemma-4-E4B-it.litertlm files/ai_models/gemma-4-E4B-it.litertlm
adb shell run-as com.nihaisha.nihaisha_app ls -l files/ai_models/
```

注意：ADB 方式不经过应用内 SHA-256 导入校验，需要自行核对上文哈希。模型加载优先尝试 GPU；GPU Engine.initialize() 失败时会在加载阶段尝试 CPU。若 GPU 初始化成功但首轮推理出现 LiteRT-LM 明确的 `Can not find OpenCL library on this device` 错误，应用会先关闭旧 Conversation 和 Engine，再重建 CPU Engine/Conversation，并只重试该首轮一次。其他运行时错误、CPU 重试失败及已有成功对话轮次后的 GPU 故障不会自动重放。界面显示实际后端，所有回退路径仍需 Find N2 实机验证。

## 当前实现范围

- 完全离线：推理在 Android 本地执行，没有模型 API、远端服务或模型自动下载。
- 文字输入与多轮文字问诊。
- 相机拍摄舌象照片：本地检查文件完整性、文件大小和最低分辨率，再由 E4B 做可见特征描述。
- 最长 30 秒语音录制：WAV、16 kHz、单声道，直接交给 E4B 本地音频输入。
- 将应用独立记录的用户文字输入和待核对语音识别草稿整理为固定字段；提取使用独立临时会话，不包含舌象图片或模型图像描述；用户核对确认后才返回规则问诊页面。
- 模型加载、会话重置、释放模型内存。会话重置若无法安全关闭旧会话或创建新会话，会尽力关闭引擎并清空运行态；页面同步读取状态，模型需重新加载，不保留半初始化引擎。
- 初始化和推理都运行在单线程后台执行器，不阻塞 Flutter UI。
- GPU 初始化失败时会在模型加载阶段回退 CPU；若 GPU 初始化成功但首轮推理命中明确的 `Can not find OpenCL library on this device` 错误，会关闭 GPU 会话/引擎、重建 CPU 会话并仅重试该首轮一次。其他推理错误、CPU 重试失败以及已有成功对话轮次后的 GPU 故障均不会自动重放。
- 模型提示词限制其职责为健康信息澄清与自述整理，不允许六经辨证、开方或修改剂量。
- AI 对话和结构化草稿不写入 DiagnosticEngine，不自动映射问诊选项，不改变既有规则辨证结果。

## 附件输入边界

音频和图片附件统一执行以下原生输入约束：

- 文件必须位于应用缓存目录内；原生层先解析 canonical path，再校验缓存目录边界，拒绝目录穿越和相邻目录前缀伪装。
- 输入必须是普通文件且非空。
- 文件大小上限为 15 × 1024 × 1024 bytes（15 MiB）；恰好达到上限允许，超过上限拒绝。
- 音频仍限制为最长 30 秒、WAV、16 kHz、单声道。
- 图片在 Flutter 选取/恢复阶段解码检查，短边至少 480 px；相机输出最大边限制为 1600 px。原生入口再次使用 `BitmapFactory` 的 bounds-only 模式检查实际文件尺寸，拒绝无法识别、短边不足 480 px 或长边超过 1600 px 的图像；该检查不完整解码位图，避免在原生校验阶段额外分配整幅图像内存。

CI 的 Kotlin 单元测试覆盖缓存目录内嵌套文件、恰好达到 15 MiB、超过上限、缓存目录外路径/相邻前缀目录，以及目录/缺失文件/空文件拒绝；图片策略测试覆盖 480 px 与 1600 px 边界、越界尺寸和无法解码尺寸。自动化测试验证的是路径和输入边界，不替代设备文件系统、录音和拍照链路的实机验收。 WAV 策略测试还覆盖 RIFF 主体截断、奇数长度扩展 chunk 的 padding、重复 `fmt ` / `data` chunk、无音频数据、错误编码参数和 30 秒边界。Flutter 界面回归测试覆盖对话重置与模型释放后的状态切换。

## 尚未接入

语音播报、经实机校准的清晰度/模糊度检测，以及已确认症状到规则问诊选项的显式映射仍未接入。当前照片检查只覆盖文件、分辨率和尺寸，不代表已完成完整的舌象图像质量评估。后续必须逐项实现并测试，不能将模型原始回复直接作为辨证输入。

## Find N2 实机验收步骤与通过条件

必须使用 OPPO Find N2（PUG110，16 GB）进行以下验收；CI APK 编译通过不能替代本节。

### 1. 安装与离线条件

- 安装本轮 CI 生成的 Debug APK，确认 Android 包名为 `com.nihaisha.nihaisha_app`。
- 将模型复制到应用私有目录，核对文件大小为 `3,659,530,240` bytes，SHA-256 与上文一致。
- 开启飞行模式，并确认 Wi-Fi、移动数据均关闭后再启动应用。
- **PASS**：模型文件状态正确；离线状态下可加载模型、连续发送文字并收到回复；抓取日志没有模型网络请求。
- **FAIL**：要求联网、下载模型、文件校验不通过却仍开始推理，或应用崩溃。

### 2. 文字问答

- 冷启动后首次加载模型，记录加载耗时、实际后端和峰值内存。
- 连续完成至少 10 轮不同问题；中间穿插重置会话，再完成 3 轮。
- **PASS**：每轮均返回非空文本；重置后不复用旧会话上下文；前台 UI 可响应；无进程被系统杀死。若首轮 GPU 推理出现明确 OpenCL 库缺失错误，界面最终显示 CPU，首轮只重试一次并成功；若没有触发该错误，记录实际后端即可。
- **FAIL**：会话串线、空回复、主线程长时间阻塞、崩溃或系统杀进程。

### 3. 音频输入

- 录制 5 秒普通话、15 秒连续描述、25 秒带停顿描述各一段。
- 录音文件应为 WAV、16 kHz、单声道；最长录音不能超过 30 秒。音频文件进入原生推理前还必须通过应用缓存目录、普通非空文件及 15 MiB 大小上限校验。
- **PASS**：离线模型返回与录音相符的逐句转写；听不清处明确标记，不补写症状；用户可移除附件并重新录音。
- **FAIL**：静默丢失录音、附件被覆盖、越过 30 秒或 15 MiB 限制，或模型把不确定语句改写成确定症状。

### 4. 舌象照片输入

- 分别拍摄正常光线、偏暗、反光、轻微失焦四种照片；每次发送前检查预览。
- 图片文件进入原生推理前必须通过应用缓存目录、普通非空文件及 15 MiB 大小上限校验；短边至少 480 px，处理尺寸最大边不超过 1600 px。
- **PASS**：模型只描述可见颜色、舌体形态和舌苔；不输出六经辨证、疾病诊断、方剂、药物或剂量；失败图片可以移除并重拍。
- **FAIL**：把照片观察自动写进用户自述草稿，或模型直接作辨证/处方结论。
- 注意：当前客户端没有经实机校准的模糊度、曝光或色温阈值；这组测试只验输入链路和输出边界，不代表图像质量检测已经完成。

### 5. 资源与稳定性

- 连续执行 10 轮文字问答、3 段音频、5 张图片；随后释放模型，再次加载。
- **PASS**：记录加载、首轮回复和各任务耗时；释放后可再次加载；无持续增长导致的 OOM 或系统杀进程。
- **FAIL**：释放期间仍有推理任务、资源无法重新初始化、持续 OOM 或严重热降频导致任务无法完成。

### 6. 记录模板

每次测试填写：APK commit SHA、设备型号/系统版本、模型 SHA-256、飞行模式状态、加载耗时、后端、失败阶段（Engine 初始化/Conversation 创建/文字/音频/图像推理）、首轮/多轮耗时、任务结果、峰值内存、温度/降频现象、失败日志。未测试项目标记 `MISSING`，不得写成 PASS。
