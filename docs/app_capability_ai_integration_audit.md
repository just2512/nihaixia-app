## 当前最重要的架构判断

1. **统一入口并非从零开始。** 首页的本地 AI 对话已是主入口，问诊、学习和工具调度已有统一消息时间线与状态机。下一步应收敛导航和会话体验，而不是再造第二个聊天页面。
2. **AI 不应直接执行计算。** 意图识别和参数澄清可以由模型辅助；规则问诊、排盘、五运六气和剂量换算必须调用确定性 App 引擎，返回结构化结果与来源。
3. **知识库可以被本地模型调用，但当前是受控上下文注入。** 检索结果应携带资产路径、原文/讲稿类型、版本状态；检索不到必须显式 MISSING。后续再评估语义索引，不应先引入无必要的向量服务。
4. **经典和医案必须分开建立来源账本。** 讲稿不能冒充古籍原文；本地文本资产不能自动视为完成版本校勘；医案内部序号不能冒充原始病例页码。

## 未完成项与验收门槛

### A. 经典条文与医案出处

- [ ] 为每条经典命中建立稳定 ID、书名、篇章、版本/底本、卷次/页码、原文片段、异文说明和核验状态。
- [ ] 将讲稿、整理讲义、古籍原文分型，禁止跨类型拼接成“原文”。
- [ ] 为每条医案建立原始出处定位；没有来源的记录继续标记 MISSING，不参与疗效证据推断。
- [ ] 建立重复条文、异文、标题误匹配和引用回链测试。

### B. 内外屏体验重构

- [ ] 建立设备姿态/窗口尺寸断点，而不是只按宽度缩放。
- [ ] 内屏采用双栏/主从布局：输入与导航、结果/盘面分区；外屏采用单列优先级布局。
- [ ] 检查所有表单、弹窗、命盘、工具页面的横向溢出、键盘遮挡、滚动和返回路径。
- [ ] 使用真实 OPPO Find N2 内屏展开/外屏折叠验收；模拟器尺寸测试只作为回归，不替代真机验收。

### C. 统一问诊流程

- [ ] 保留一个会话 ID、一条消息时间线、一套历史恢复逻辑。
- [ ] 自由对话症状澄清与结构化辨证控制器必须在同一会话内衔接；结构化问诊不是另一个独立聊天产品。
- [ ] 核对旧 `ChatScreen` 和所有导航入口，清除重复问诊入口或明确迁移兼容策略。
- [ ] 规则引擎只消费用户确认的 canonical answers；模型抽取内容必须经用户确认后才能进入规则状态。

### D. 知识库与工具

- [ ] 对检索器增加来源元数据与检索状态类型，禁止只把长文本拼入 prompt 后丢失引用关系。
- [ ] 工具调用统一为 `tool_id + validated_arguments + execution_result + provenance`。
- [ ] 每个工具必须定义必填参数、缺参澄清、参数校验、取消、失败恢复和结构化回传。
- [ ] 对模型不可用、检索失败、索引缺失、工具异常分别给出明确状态。

### E. 全 App 盘点

- [ ] 建立页面/功能/数据资产/工具注册表的可追踪清单。
- [ ] 逐项标记：保留、合并、迁移、废弃、缺测试、缺来源。
- [ ] 识别知识页、工具页和 AI 对话中的重复入口，按统一调度入口收敛。
- [ ] 不以“路由注册存在”作为功能完成；必须通过页面级与端到端用例。

## 分支集成规则

- 本审计基线为 `e327a60c999ec87b42f3d067de41c492ebb3fc6c`。
- 各专题分支只修改各自领域文件；跨域接口先定义稳定契约，再集成。
- 不在专题分支中同步上游整支代码，不覆盖 Fork 的自定义药名映射。
- 每个分支独立通过针对性测试后再合入；最终集成必须跑完整 Flutter 回归和 Android 构建。


## 2026-11-06 并行功能落地记录

本轮已将以下实现合入 integration，不代表最终整体验收完成：

### 1. AI 统一助手

- AssistantToolArguments.validateAgainst 在页面执行前校验 tool_id、未声明参数、必填项、日期、整数和枚举值；参数不合规时拒绝执行。
- AssistantToolResult 增加结果身份校验与 sourceIds；来源标识缺失时输出 MISSING。
- 旧页面返回的字符串结果统一包装为 typed result，避免新旧返回格式直接混入同一消息时间线。
- 当前仍需逐工具补齐参数定义、执行状态、取消/失败恢复；尚未把所有工具页面迁移到结构化结果。

### 2. 中医知识工具

- 经典检索命中增加 sourceId、localBacklink、locatorStatus，上下文保留讲稿/古籍类型与本地回链。
- 医案检索上下文直接携带逐条来源账本字段；内部序号只作为 App 数据主键，不再冒充原始出处。
- 经典文本的版本、底本、卷页仍未逐条核验；检索回链目前是 App 内部资产定位，不等于已建立可跳转的阅读路由。

### 3. 紫微布局

- 展开屏宽度达到 700dp 时，输入卡与排盘摘要并列；窄屏保持单列。
- 命盘盘面在宽屏最大 640dp 居中，在外屏按可用内容宽度布局。
- 测试先滚动懒加载列表再检查盘面尺寸，避免把未构建的 Widget 误判为布局缺失。
- OPPO Find N2 真机内外屏、铰链姿态、键盘遮挡和弹窗路径仍需实机验收。

### 4. 经典医案来源账本

- 新增 assets/medical_cases/source_ledger.json，按医案内部序号建立逐条记录；当前账本覆盖来源表中解析出的记录。
- 默认字段全部为 MISSING。只有原始书名/病例来源、版本/底本、卷次、页码、篇章/病例标题齐全且显式标记 VERIFIED，状态才会显示为 VERIFIED。
- 目前没有凭摘要或内部序号补造任何原始出处；后续只录入可核对的来源。

### 5. App 整合

- 首页一级导航收敛为 AI、收藏、设置；知识库浏览入口注册到统一助手学习模式，原工具页能力通过助手角色对应的入口菜单调用。
- 统一助手仍是唯一默认对话入口；旧 ChatScreen 的全仓引用与历史路由迁移审计尚未完成，不能宣称重复入口已经全部清除。

### 当前验收边界

- 专题分支定向 CI 已分别验证 AI 契约、知识来源元数据、医案账本、首页导航和紫微布局的对应改动；以各分支最新 SHA 的运行结果为准。
- integration 的完整 Flutter 回归和 Android APK 构建仍以最新集成提交对应的 CI 结果为最终门槛。
- 任何 MISSING 来源不得被模型改写成已核验引文；任何未通过参数校验的工具调用不得进入执行页面。
