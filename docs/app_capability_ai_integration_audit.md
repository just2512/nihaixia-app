## 当前最重要的架构判断

1. **统一入口并非从零开始。** 首页的本地 AI 对话已是主入口，问诊、学习和工具调度已有统一消息时间线与状态机。下一步应收敛导航和会话体验，而不是再造第二个聊天页面。
2. **AI 不应直接执行计算。** 意图识别和参数澄清可以由模型辅助；规则问诊、排盘、五运六气和剂量换算必须调用确定性 App 引擎，返回结构化结果与来源。
3. **知识库可以被本地模型调用，但当前是受控上下文注入。** 检索结果应携带资产路径、原文/讲稿类型、版本状态；检索不到必须显式 MISSING。后续再评估语义索引，不应先引入无必要的向量服务。
4. **经典和医案必须分开建立来源账本。** 讲稿不能冒充古籍原文；本地文本资产不能自动视为完成版本校勘；医案内部序号不能冒充原始病例页码。

## 2026-11-07 集成基线

### 已进入 master 的能力
- 经典检索命中现在通过 `ClassicSearchService.findBySourceId()` 反查；助手回复展示来源标题、本地回链和明确的纸本版本/卷页 `MISSING`，对应 sourceId 写入 assistant 消息元数据。未反查成功的 ID 不作为引用；这仍不代表纸本校勘完成。
- AI 统一助手已采用 typed tool arguments/results；所有工具启动路径统一执行必填参数和类型校验。
- 工具执行结果与消息元数据分离保存，支持来源 ID、工具 ID 和历史恢复。
- Find N2 紫微布局使用 640dp 双栏断点与 640dp 盘面上限，避免窄屏拉伸及展开屏摘要区域缺失。
- 经典知识检索提供稳定 sourceId、精确反查和本地回链标识；本地文件标识不等同于已核验纸本出处。
- 医案逐条来源账本已接入 AI 检索上下文；出处状态必须为 VERIFIED 且定位字段完整，才可作为已核验定位，否则保留 MISSING/PENDING。

### App 入口收敛规则
- 一级导航保留 AI、收藏、设置。
- 知识库通过 knowledge_hub 复用现有页面；具体问答仍在当前统一会话中处理。
- 工具能力由统一注册表按意图路由；独立工具页面仅承担确定性输入与执行，不再复制会话历史。
- 工具注册表必须保持 ID 唯一，且每个工具都有可构造的目标页面。

### 尚未由自动化测试替代的验收
- OPPO Find N2 真机内屏、外屏及折叠/展开过程仍需设备实测；窗口尺寸测试不能代替物理设备验收。
- 经典医案纸本底本、卷次、页码未核验的条目继续标记 MISSING，不允许根据内部序号补全。
## 2026-11-07 本轮功能落地补充

### 知识来源与回链
- 方剂、本草、针灸处方、穴位、内经结构化条目、经典索引和医案记录均输出独立 `sourceId`。当前资产清点：方剂 327 条、药材 465 条、针灸处方 383 条（14 类）、穴位 408 条、医案 1256 条。
- `buildWithSourcesAsync` 对来源 ID 做反向解析；无法解析的 ID 不进入引用列表。
- 针灸处方数据中条目 ID 会跨分类重复，针灸来源 ID 固定使用 `categoryId + entryId`；仅使用条目 ID 会造成错误回链。
- 来源引用区分 `sourceKind`、本地回链、书目定位状态和纸本核验状态。数据资产路径、内部条目 ID、医案内部序号均不升级为纸本出处。
- 当前 `source_ledger.json` 覆盖 1256 条有效医案；1256 条记录的书名、版本、卷页、篇章和原文出处字段均为 `MISSING`。这是当前数据事实，不代表已完成纸本核验。

### 工具执行契约
- `AssistantToolResult` 增加实际执行参数字段，与 `toolId`、结构化结果、执行状态、来源 ID 一起构成结果载荷。
- `AssistantMessageMetadata` 保存 `toolArguments`；工具请求阶段先持久化已解析参数，工具结果阶段再次持久化实际执行参数、状态和来源 ID。
- 取消、失败、无返回值与成功保持不同终态；成功结果仍要求有结构化输出。

### 回归验收
- 工具结果消息使用 `SelectableText` 展示；对应测试按实际消息组件定位，不再使用只匹配 `Text` 的错误查找器。
- Find N2 内屏布局测试在初始排盘 microtask 完成后再检查摘要与盘面；640dp 双栏断点和盘面最大宽度保持独立测试。
- 真机 OPPO Find N2 折叠/展开、键盘遮挡、物理铰链区域和实际触控仍需设备验收，CI 窗口模拟不能代替真机。
