# AI 改造多分支并行执行协议

> 本文件是 `docs/ai-capability-audit.md` 与 `docs/ai-modernization-execution-ledger.md` 的执行方法附件。后续任何对话继续本项目时，必须先读取本文件和最新 master 台账，不得依赖聊天记忆推断分支、任务或状态。
>
> 本协议只规定如何组织工作，不降低 AI 能力审计规范中的安全、证据、测试和真机验收门槛。

## 1. 固定执行模型

采用：

`主线基线（master） → 独立工作分支（workstream branches） → 小批量集成（small-batch integration） → 自动验收（CI） → 设备验收（Find N2 TRACE）`

- `master` 是唯一集成基线；开始每轮工作先读取最新 SHA、约束文件、执行台账、打开 PR 和 CI。
- 每个工作流有独立分支、明确文件所有权、任务 ID、证据和完成定义。
- 无文件冲突且无逻辑依赖的工作并行；有接口依赖的工作先冻结接口契约，再并行实现；必须依赖行为基线的工作不得越过基线。
- 每个 PR 只集成一个可独立验证的小切片。禁止把多个未验收工作流打包合并。
- CI 通过不等于真机通过；模拟测试不等于 Find N2 TRACE；分支级 changed-tests 不等于全量回归。
- 未满足硬门槛时保持 PARTIAL/UNKNOWN，不以合并数量或代码量作为完成标准。

## 2. 每轮自动启动顺序（跨对话恢复协议）

每次继续任务时按顺序执行，不等待用户重新指定：

1. 读取 `master` HEAD 和工作区状态（GitHub 远端分支/PR/CI）。
2. 读取 `docs/ai-capability-audit.md`、本文件和 `docs/ai-modernization-execution-ledger.md` 最新版本。
3. 读取所有活动工作分支的最新 commit、变更文件、PR 状态和最近 CI；过期行号必须重新核对。
4. 对照台账为 A-G 每条工作流更新状态；将“计划”“源码存在”“测试文件存在”与实际测试结果分开。
5. 查找阻塞和依赖，自动选取所有当前可推进的最高优先级任务；一个分支受阻不得冻结无依赖分支。
6. 并行开展只读审计、独立测试、不同文件域的实现；存在共享文件写冲突时，按下文文件所有权与接口契约协调。
7. 每个小切片完成后运行最小针对性测试、analyze/format、分支验证；满足条件才创建/更新 PR。
8. 监测 CI 到结束，读取失败步骤与日志/产物；失败必须定位根因或明确 UNKNOWN，不以盲目重跑代替诊断。
9. 按集成门槛小批量合并；合并后重新读取 master SHA，并对后续分支执行 rebase/merge-base 冲突核对和回归。
10. 更新执行台账：commit、CODE、TEST、CI、TRACE、缺口、下一动作。未更新台账的改动不算交付。
11. 结束本轮前写入明确的“下一项自动执行任务”和依赖，不把任务选择留给用户逐条提醒。

若运行环境不支持后台持续运行，必须如实说明；不得声称在对话结束后仍持续监测。下一次对话按本协议从最新远端状态恢复。

## 3. 工作流分支与文件所有权

默认分支命名：`work/ai-<workstream>-<slice>`。分支必须从当前 master SHA 创建，并在任务记录中保存 base SHA、head SHA。

| 工作流 | 主责范围 | 禁止并行覆盖 |
|---|---|---|
| A 多轮稳定性 | Native Kotlin Engine/Conversation 生命周期、请求状态、fallback、重试、历史回放；相关 Kotlin/Flutter 测试 | B 不得直接修改 A 的 Native 生命周期实现；需要 Native 红旗边界时先定义接口 |
| B 红旗安全 | Dart 红旗策略、语义分类、Flutter 全入口接入和 Dart 测试；Native 接口只提交契约 | 不得与 A 同时编辑 `MainActivity.kt`；医学词表/阈值/文案未经医学审核不得正式启用 |
| C 检索基线 | ClassicSearch、KnowledgeContext、黄金测试夹具/快照 | 黄金快照锁定前不得抽适配器、改变检索算法或引入 FTS5 |
| D Capability | ToolRouter 目录审计、Page/Headless/Executed 分类；单能力适配器 | 对应能力的当前行为和来源基线未锁定前不得抽取适配器 |
| E 数据保护 | Android Manifest/XML、AI 数据清除、附件/缓存生命周期及相关测试 | 备份策略与清除全部 AI 数据分开提交；数据库加密另行决策 |
| F TRACE | 默认关闭的 trace_id、脱敏事件、跨层关联及测试 | 不得为埋点顺手改写业务路由或持久化语义 |
| G 文档/版本 | README/pubspec 版本一致性、审计报告、执行台账、文档校验 | 不得覆盖规范文件；报告与规范分离 |

允许增加临时专项分支，但必须声明其工作流归属、唯一文件所有者、依赖和撤销条件。一个文件同一时间只允许一个活动分支负责实现；其他分支通过接口契约或后续集成消费结果。

## 4. 并行调度规则

### 可并行

- A 多轮生命周期审计/实现，与 B 红旗纯 Dart 策略、C 检索行为基线、E 数据清点/备份审计并行。
- D 工具目录只读盘点可与 A/B/C/E 并行。
- F TRACE 字段/隐私方案设计可并行；跨层接入需按文件所有权排期。
- G 文档版本检查可独立执行。

### 必须串行的依赖

- B 接入 Native 模型边界前，先与 A 冻结 Native 红旗调用契约，避免双分支改同一 Kotlin 文件。
- C 先运行并保存真实黄金快照，再允许检索适配器或算法改动。
- D 先证明业务函数现状和行为基线，再抽 Headless Capability。
- E 清除全部 AI 数据前，先盘点数据库表、附件原件、缩略图、临时文件、缓存和引用关系。
- E 备份策略 PR 必须验证 Android merged manifest 与构建；全应用禁用备份的产品影响必须记录。
- 所有涉及医疗安全门禁的正式放行，必须等待医学审核记录与全入口负向测试。
- Find N2 GPU/CPU、图片/语音、进程恢复等实机验收只能由真实设备运行产生，不能由 CI 代替。

## 5. 小批量集成门槛

每个切片必须具备：

1. 单一目标和明确失败场景/缺口。
2. 文件变更范围符合所有权，不夹带无关格式化或重构。
3. 对应单元/集成测试，覆盖正常、边界、失败路径。
4. 静态分析/格式检查通过。
5. 分支 CI 通过；若 workflow 跳过全量测试或 Android build，必须明示。
6. PR 描述列出基线 SHA、改动文件、验收场景、风险、回滚方式和未完成项。
7. 集成前检查 master 是否前进、冲突是否改变语义、测试是否仍覆盖最终合并树。
8. 任何硬门槛 UNKNOWN/FAIL 时不得把相关能力标为完成；是否合并纯文档/独立安全改动，按风险单独判断，不得借此放行未验收能力。

默认不直接合并仍在运行 CI 的 PR。PR 的 `mergeable=true` 只表示 GitHub 认为可合并，不代表质量门槛通过。

## 6. 自动验收分层

| 层级 | 内容 | 能证明什么 | 不能替代什么 |
|---|---|---|---|
| L0 | format、静态检查、编译/契约检查 | 代码基本一致性 | 运行行为 |
| L1 | changed tests、专项单测/集成测试 | 变更切片行为 | 全量回归 |
| L2 | Flutter 全量回归、Android manifest merge/build、APK 构建 | 仓库级回归与 Android 构建 | 真实设备运行 |
| L3 | Find N2 真机 TRACE，GPU/CPU、跨轮、附件、恢复 | 指定设备/版本/backend 的真实行为 | 未覆盖设备/场景 |
| L4 | 端到端来源/执行审计 | 输入到最终展示、业务结果、持久化闭环 | 未执行的场景 |

CI 失败处理：
- 先读 job/step、失败日志、测试 diff 和 artifact。
- 将失败归为代码回归、环境/依赖、已有基线失败或 UNKNOWN，必须有证据。
- 只在确认是可重试基础设施故障时重跑；测试断言失败先复现和定位。
- 当前 master 的失败不得自动归因到其他分支或最新提交；用 SHA 和对照运行确认。

## 7. 状态与证据同步

每个任务沿用执行台账的状态：`NOT_STARTED / IN_PROGRESS / PASS / PARTIAL / FAIL / BLOCKED / UNKNOWN`。每次状态更新至少记录：

- Task ID、工作流、分支、base SHA、head SHA；
- 改动文件及 CODE 定位；
- TEST 命令/测试名和实际输出；
- CI workflow/run ID/head SHA/结论/失败步骤；
- TRACE 设备、Android、App SHA、模型版本、backend、场景和轮次；
- 当前缺口、外部依赖、回滚方法；
- 下一项可自动执行任务。

`PASS` 只适用于该条任务的全部验收条件；部分通过写 `PARTIAL`。没有日志、设备或源码证据写 `UNKNOWN`。不得将子项 PASS 扩大为整个工作流 PASS。

## 8. 默认任务优先级与自动选活规则

按约束文件和真实证据执行，而不是按容易程度执行：

1. 修复/定位当前主线阻断性 CI 回归，建立可复现基线。
2. A：多轮执行状态安全、fallback transcript 回放、二次异常保留、请求未知状态禁止盲目重放。
3. B：纯 Dart 红旗 preflight 与语义测试；医学审核未完成前保持 REVIEW_REQUIRED，不发布未经审核词表。
4. E：验证 Android merged manifest/build；盘点并实现清除全部 AI 数据及附件缓存，重启后不可恢复。
5. C：生成并提交真实检索黄金快照，验证 query/hits/order/source/context；在此之前禁止重构检索。
6. D：完成 Page/Headless/Executed 盘点，再按证据抽取最小适配器。
7. F：默认关闭 TRACE 的端到端贯穿和隐私测试。
8. G：README/pubspec 版本同步和防漂移检查。
9. 按审计规范逐项执行场景集 L/C/T/M/A/X；不能在设备上执行的场景保留 UNKNOWN。

若高优先级任务被外部依赖阻塞，立即推进所有无依赖的下一项，不空等、不虚报。

## 9. 禁止事项

- 不得因“并行”而让多个分支同时修改同一文件。
- 不得从过期分支整分支合并到 master；只能按文件/提交审查并验证。
- 不得以文档分支 CI 通过声称 Flutter 全量或 Android 构建通过。
- 不得把设备未提供的结果写成真机 PASS。
- 不得自动合并未通过质量门槛、存在安全/数据风险或需要用户产品决策的变更。
- 不得在聊天中承诺跨会话自动记忆；本协议与执行台账才是项目续接依据。

## 10. 当前项目启动清单

后续每轮按实际远端状态刷新，不将以下初始状态永久化：

- [ ] master SHA 与两份约束文件 SHA 已核验。
- [ ] 活动分支、PR、CI 已逐项核验。
- [ ] A/B/C/D/E/F/G 状态已与证据同步。
- [ ] 所有可并行任务已启动；共享文件冲突已排除。
- [ ] 下一任务和依赖已写入执行台账。
