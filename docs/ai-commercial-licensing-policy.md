# AI 增值功能商业授权政策

## 1. 目的和产品定位

本政策将仓库中的功能分为两层：

- **免费基础层：** Fork 原有功能、确定性业务模块和知识库，继续按原许可证免费使用。
- **AI 增值层：** 维护者自主开发的本地 AI 理解、对话、问诊衔接、助手编排、工具调度、上下文组织及结果解释功能，可由维护者对官方发行版提供商业授权。

本软件的定位是中医学习工具。AI 用于帮助用户理解、整理、追问和解释已核验的信息；确定性业务仍由既有模块执行。不得把收费策略描述成云端医疗诊断服务。

## 2. 授权结构

### 2.1 当前公开版本的许可证状态

本次审计基线 `master@a886286de83116fef8193db3781a11dca6ff8ece` 的根目录 `LICENSE` 是 Apache License 2.0，README 亦将项目整体声明为 Apache 2.0。当前基线尚未为 AI 文件设置商业许可证例外。因此，本次已公开的 AI 代码仍按当前公开版本适用的 Apache 2.0 权利执行。

本政策文件和商业授权草案本身不会改变当前代码的许可证，也不会让已经公开的 AI 文件自动转为收费专有代码。

### 2.2 已公开版本的既有权利

对在本政策切换前已经公开发布、并按根目录 Apache 2.0 许可证提供的源码，接收者继续保留对应版本已经取得的 Apache 2.0 权利。

- 不要求此前下载、克隆或构建该版本的人购买商业授权。
- 不要求接收者将其现有 Apache 使用方式改为商业授权。
- 不追溯要求付费，不以本政策撤销或缩减已经授予的许可。

### 2.3 未来官方版本的 AI 商业授权切换

维护者可以从指定的未来官方版本开始，对自己拥有权利的 AI 增值代码启用商业授权。切换必须在实际发行版本中完成，不能只靠本政策文档生效。

每个切换版本必须同时做到：

1. 发布明确的许可证切换版本号、build 号和源代码 commit SHA。
2. 发布该版本专用的 AI 商业模块文件清单（release manifest），列出每一个适用商业许可的文件路径。
3. 对纳入商业许可的独立 AI 文件添加清晰的文件级许可标识，例如 `SPDX-License-Identifier: LicenseRef-Hantang-AI-Commercial`，并在根目录许可说明中明确列出 Apache 2.0 的适用范围及商业许可例外。
4. 确保商业许可文件只包含维护者拥有权利的 AI 代码；任何包含上游、第三方或免费业务逻辑的混合文件，先拆分再列入清单。
5. 旧版本继续按旧版本许可证执行；任何人可以继续使用已取得的旧版 Apache 代码，不追溯收费。

**特别说明：** 当前列出的 AI 文件是商业模块候选边界，并不表示这些文件在当前公开 master 上已经完成许可切换。未来版本可以将维护者拥有版权的 AI 模块以商业许可方式提供；此前相同代码的公开 Apache 版本仍保留其原有授权。

### 2.4 双重授权的适用方式

对于维护者拥有版权的 AI 代码，维护者可选择同时提供两条授权路径：

- **历史公开源码路径：** 接收者对已经按 Apache 2.0 发布的版本，继续使用该版本的 Apache 2.0 许可。
- **官方商业发行路径：** 对切换版本中被 release manifest 明确列出、并通过文件级声明排除在 Apache 2.0 之外的 AI 模块，向官方商业版用户提供本协议中的商业许可。

双重授权是维护者对自己代码提供不同授权选项的方式；它不撤销旧版本已授予的 Apache 权利，也不把知识库、确定性业务引擎或第三方代码纳入商业范围。

### 2.5 公开源码与官方商业版的区别

本仓库可以继续公开基础应用源代码，同时对未来版本中明确列入商业清单的 AI 模块采用独立商业许可。源码可见不等于该文件必然适用仓库根目录许可证；但必须通过清晰、逐文件、逐版本的许可声明确定适用范围。

如果某个文件仍被根目录 Apache 2.0 覆盖，或没有被有效地列为商业许可例外，则不得仅以本政策、README 文案或“由维护者提交”为由声称该文件已经收费专有。
## 3. 用户授权原则

官方商业版的终端用户授权，原则上采用个人使用、非独占、不可转让的许可。授权范围和设备数以实际购买页面及订单凭证为准。

商业许可不授予：

- 将官方商业版 APK 或授权凭证重新打包、转售或公开分发的权利；
- 通过破解、伪造授权凭证等方式规避官方发行版授权校验的权利；
- 使用本项目商标或名称暗示官方背书的权利。

任何限制均不得剥夺用户依照适用法律不可排除的权利，也不得限制用户对已按 Apache 2.0 获得的代码副本行使该许可证明确授予的权利。

## 4. 本地推理和数据边界

商业化不得改变既定的本地隐私架构：

- AI 推理在用户设备本地完成，不接入云端模型推理。
- 用户输入、问诊记录、对话历史、图片、音频、检索内容及 AI 结果留在本地。
- 授权校验不得上传上述内容。
- 如将来需要联网激活，只能处理实现授权所必需的最少订单/授权状态信息，并应在上线前另行披露；不得把用户内容作为授权校验数据。
- 断网可用性、离线授权恢复和换机策略必须在正式收费前确定并验收。

## 5. 授权边界

具体文件和功能以 [AI 增值模块边界清单](ai-commercial-module-boundary.md) 为准。

下列范围不收费，也不纳入本商业许可：

- 上游 Fork 原有代码与免费基础功能；
- 确定性中医辨证、计算和排盘业务引擎；
- 知识库、经典资料、本草、穴位、医案、讲稿及其他内容；
- 第三方模型、运行库和依赖；
- 用户自己的本地数据。

AI 模块读取或检索知识库，只代表 AI 逻辑调用这些数据，不意味着知识库内容被纳入商业授权。

## 6. 新增代码与权利来源

后续 AI 增值功能必须由维护者实际拥有版权或取得足够授权后，方可纳入商业授权范围。

- 新功能优先拆成独立 AI 模块。
- 不对包含上游代码的整个混合文件主张独占版权。
- 外部贡献者提交的代码按适用贡献协议及其实际权利来源处理。
- 第三方模型权重、原生运行库和依赖仍按第三方许可证执行。
- 每个正式发行版应保存对应的 AI 模块清单和源代码提交 SHA。

## 7. 正式启用前的发布门槛

以下事项全部确定后，商业授权才随指定版本正式生效：

- [ ] 指定商业授权生效的发行版本、源代码切分提交 SHA，并生成该版本专用的 AI 商业模块 release manifest。
- [ ] 对纳入范围的独立 AI 文件添加清晰的文件级许可标识，并在根目录许可说明中明确 Apache 适用范围及商业例外。
- [ ] 混合文件中的原有代码和新增 AI 代码完成拆分或精确标注。
- [ ] 官方 APK 的授权状态、无效授权和离线恢复路径完成测试。
- [ ] 价格、有效期、设备数、换机、续费和退款规则在购买页面明确。
- [ ] 随正式安装包提供 Apache 2.0 与其他必要的第三方许可文本。

在上述门槛完成前，本政策用于界定商业化方向和代码边界。当前公开 master 的 AI 代码仍按其现行 Apache 2.0 许可执行；商业许可只从另行声明的未来切换版本起生效。
