## 产品定位与安全边界（2026-11-15，优先级最高）

权威产品准则见 [产品定位与开发边界：中医诊疗全过程学习](product-positioning-and-boundaries.md)。该文件与本节共同约束产品开发；发生冲突时，以该产品准则为准。

- 本软件是**中医诊疗全过程辅助学习软件**，目标是帮助用户学习并练习问诊、辨病、辨证、病机分析、治法确定、方剂配伍、针灸思路、经典依据和医案复盘。
- 问诊助手是**模拟辨证演练**。输入可以是用户自己的身体体验，也可以是书籍、经典或历史医案；AI 负责保留原话、引导补问、解释提问理由，并结合 App 原有规则结果完成病例层面的辨病辨证教学。
- 学习内容不得缩减为“只演示辨证”。针对模拟病例，必须继续讲解病机、治法、方剂组成与配伍、针灸选穴思路及相关依据；不得把诊断和治疗教学本身视为禁止内容。
- 模拟病例的辨病辨证结论和治疗方案属于学习分析，不得包装成对用户或他人现实疾病的诊断，也不得转化为要求现实个人按方案用药、停药、调整剂量或实施治疗的指令。
- 问诊开始、进行中和结果解释阶段固定显示免责声明：本问诊用于中医诊疗全过程的模拟学习与病例推演；辨病、辨证、病机、治法、方剂及针灸内容均为学习分析，不构成对现实个人的医疗诊断或治疗指令；现实身体不适应及时就医；不得仅依据模拟结果自行诊断、用药、停药或实施治疗。
- 同一固定提示包含简单急重症提醒：如胸痛、明显呼吸困难、意识不清、抽搐或大量出血等情况，请立即拨打 120 或前往急诊。该提醒是一般性求助提示，不是临床分诊、风险分级或疾病检测器。
- 不建立五类临床红旗规则库、YAML 医学规则系统、临床召回率指标或医师签字流程作为模拟学习功能的准入条件；不得因缺少这些材料阻断正常学习演练。
- App 原有问诊控制器和确定性规则负责题目、选项、辨证执行与结果生成；AI 负责语义理解、引导追问、规则结果解释和知识串讲，不得篡改规则或虚构业务结果。
- 学习助手必须优先复用现有 `AssistantKnowledgeContextBuilder`，串联方剂库、古籍索引、倪师医案及现有针灸/穴位资料，并为可引用内容提供稳定 `sourceId` 和 App 原详情页入口。

本节优先于本文及历史审计报告中将问诊缩减为“只演示辨证”或按临床分诊系统建设的旧要求。历史记录可保留作决策轨迹，但不得作为当前产品边界。

## 1. 目标与问题定义

目标不是“接入 Agent”或重建一套 AI 架构，而是让五种模式在真实场景中形成可追踪、可验证、受约束的任务闭环：

`用户输入 → 安全检查 → 意图/实体理解 → 检索与上下文组装 → 模型决策/解释 → 参数校验 → 业务执行 → 结果核对 → 结果展示与跨轮延续`

**首要交付是失败分类证据，不是功能清单或架构图。** 每个失败场景必须归入以下类别之一；若证据不足，标 UNKNOWN，不得猜测：

| 类别 | 判定 | 优先排查位置 |
|---|---|---|
| 理解失败 | 意图、复合子目标、指代或实体识别错误 | Orchestrator、实体解析、槽位提取 |
| 检索失败 | 应召回的资料未命中、命中错误或排序遗漏 | Repository、索引、别名与检索策略 |
| 上下文失败 | 已召回资料未正确注入、被错误截断/压缩或来源丢失 | Prompt/Context Builder、长度预算、历史拼装 |
| 执行失败 | 工具未调用、参数错误、业务执行失败、结果未回传或被忽略 | ToolRouter、能力适配层、业务函数、结果协议 |
| 模型能力上限 | 输入、检索、上下文、工具结果均正确，模型仍无法完成受限任务 | 任务缩小、分步、模板化或接受模型边界 |

不得将上述类别混为“AI 不聪明”。不得在失败分类尚无场景证据时，以建设统一核心、Agent、DAG 或更换模型作为默认修复。

## 2. 架构约束：复用现有系统，不另起炉灶

### 2.1 八层仅作对照检查表

用户交互、安全、知识业务、状态记忆等层优先核实现有代码对应物。每层必须记录“现有文件/函数、实际调用方、测试证据、缺口”，不得将八层直接拆成八个新模块或八项重构工程。

重点验证的缺口是：
1. 意图理解到复合任务与缺参澄清；
2. 页面入口背后的业务函数能否脱离 Widget/BuildContext 独立调用；
3. 多个可信业务结果能否按来源约束综合解释并展示。

### 2.2 明确禁止的重复建设

未经审计证明必要且获得项目决策确认，不得：
- 重建 AIWorkbench、五种模式、Orchestrator、ToolRouter 或会话/消息数据库表；
- 新建通用 Agent 平台、DAG 工作流引擎或复杂任务图；
- 以“统一架构”为由把现有规则问诊、知识库和业务算法迁移到模型；
- 先引入向量数据库、Embedding、LangChain、云端模型/API 或原生 Function Calling；
- 把学习测验、批改、复习计划等新产品功能混入 AI 核心改造。此类功能需独立立项，明确是否新增学习状态存储。

实现优先采用小型线性任务计划；若确有多步需求，先使用最多 5 步的顺序计划和显式引用，不引入 DAG。不得为了架构整齐而复制已有状态或业务逻辑。

## 3. 端侧 E4B 的职责分工与预算

必须遵守“代码确定性、模型语义性、代码执行与验证”的边界：

| 环节 | 责任方 | 允许职责 |
|---|---|---|
| 红旗与安全门禁 | Dart/原生确定性代码 | 输入检查、急症红旗、领域权限、拒绝条件；不得只依赖 system prompt |
| 初步路由 L0 | Dart | 稳定规则、模式约束、缩小候选域 |
| 候选工具筛选 | Dart + E4B | 代码将候选缩小到最多 5–6 项；模型在受约束结构中选择或请求澄清 |
| 实体解析与槽位 | 代码优先，模型辅助 | 输出候选实体/槽位；ID、类型、必填项由代码核验 |
| 检索与上下文 | Dart | 明确来源、条数、字符/token 预算、截断状态及失败状态 |
| 业务执行 | Dart 业务函数 | 参数校验、确定性计算、权限检查、错误处理 |
| 结果核对 | Dart | 校验返回类型、完整性、单位、来源和执行状态 |
| 综合解释 | E4B | 仅根据已验证结果组织语言；区分事实、规则、App 数据和 AI 归纳 |

不要求每轮都调用模型做规划。简单单意图请求可走确定性路径；复杂或歧义请求才进入模型辅助选择/槽位提取。结构化输出必须有 schema、解析失败处理和重试上限，不得把自由文本 JSON 当作可信参数。

**预算要求：**
- 每次模型调用记录模型/后端、轮次、输入字符数、可取得时的 token 数、输出字符数、耗时和异常。
- 不得把字符数冒充 token 数；token 统计能力不存在时写 UNKNOWN。
- Prompt/context 必须分段记录来源与预算；超限应按条目边界和优先级裁剪，并显式标记哪些来源被省略。禁止无提示地从任意字符位置截断而仍声称上下文完整。
- 上下文预算以 Find N2 实测可稳定运行的值确定，不从其他手机的公开性能数据推算。

### 3.1 用户可选择本地推理后端

- E4B 的 GPU / CPU 必须允许用户在 App 设置中手动选择，Debug 与 Release 均可使用；首次安装或没有已保存偏好时使用 GPU 优先。
- 用户选择偏好与 Native 实际运行 backend 必须分开记录和展示。GPU 初始化或推理后发生 CPU fallback 时，不能把用户选择的 GPU 当作实际运行结果。
- 运行中切换后端必须经过现有 Native 串行任务队列，安全释放旧 Engine/Conversation 后再初始化目标后端；只恢复已确认成功的历史轮次，不自动重放正在执行或状态未知的请求。
- 目标后端初始化失败必须向用户显示失败，并允许其手动选择另一后端重试；不得要求通过后台修改配置、ADB Intent 或重装 App 才能切换。
- GPU 模式沿用 App 当前 EngineConfig 的图形/视觉后端配置；语音实际后端按 Native 配置单独核验。不得将所选 backend 等同于实际 backend。

## 4. 三种领域硬边界

### 4.1 玄学大师

- 排盘、起卦、历法、干支与数值计算必须调用 App 确定性业务逻辑；模型不得心算伪造计算结果。
- 必要输入缺失（例如出生时辰、日期、地点或起卦条件）时必须追问；不得静默补默认值、推测时辰或替用户选择算法。
- 例外仅限工具契约已明确声明为 optional、且 App 既有执行器已定义同一默认口径的参数：默认值必须由 App 确定性代码生成，并在执行结果的实际 arguments/会话 metadata 中记录解析后的值；模型不得生成默认值，必填参数绝不适用此例外。
- 输出明确分区：**计算结果**（App 业务函数返回）与**文化性解读**（AI 归纳），并标注采用的输入和算法。
- 玄学请求不得调用问诊、诊断、处方或剂量能力。

### 4.2 问诊助手：模拟辨证演练

- 用户输入可以来自自身体验、书籍案例、经典医案或假设病例；均作为模拟学习素材处理。保留原始表述，候选症状须标明确认状态，未知信息不得自行补齐。
- AI 负责理解自然语言、引导补问、指出缺项并解释“为什么还要问这一项”；例如怕冷、发热之后，继续追问汗出、口渴、恶风等信息，并说明这些信息如何影响表证鉴别。
- 题目顺序、选项、规则辨证过程和确定性结果由 App 现有 `TcmInterviewConversationController` / `DiagnosticEngine` 执行；AI 不修改规则、不虚构规则结果，也不把自己的推断冒充规则引擎输出。
- 规则结果形成后，AI 必须继续面向模拟病例解释辨病、辨证、病机及证据链，并进一步教学治法、代表方、方剂组成与配伍思路、针灸选穴和配穴思路；不得只输出证名或只展示辨证过程而省略治疗教学。
- 可以讲解模拟病例的完整治疗思路和方案，包括有来源支持的原方组成、历史用量或资料记载的用法；必须说明资料来源与学习语境，不得转化成对现实个人的服药、停药、调量或实施治疗指令。
- 问诊开始、进行中和结果解释时固定显示产品准则规定的免责声明及简单急重症提示。急重症提醒只作一般性及时求助提示，不开展临床分诊，不要求临床 detector，也不因 detector 或医师审核缺失而阻断学习演练。
- 若用户说明现实身体不适，提醒及时就医；可以继续把其描述作为模拟素材讲解，但不得把模拟结论表述为该用户的现实诊断或个人治疗指令。

### 4.3 综合层与来源

每条实质性结论必须可区分以下来源类型：
- `知识库条目/原文`：来自 App 已有知识库的具体记录；引用必须附稳定 `sourceId` 和 App 内可打开的条目定位（例如资产路径 + 章节/条目 ID、医案内部记录 ID）；
- `规则结果`：DiagnosticEngine 或其他确定性规则引擎实际返回的结果；
- `App 数据`：本地数据库、计算器或业务函数实际返回的数据；
- `AI 归纳`：模型对上述已提供资料或已校验业务结果的解释、比较和综合。

不得把 AI 归纳伪装成原文、规则结果或 App 计算值。对本地知识库已有且可定位的内容，App 内条目定位就是本项目普通知识问答的来源验收标准；不要求为每条学习资料再补外部纸本版本、卷次、页码或影印本坐标。只有本地条目不存在、检索未命中/失败、`sourceId` 无法解析或打开、或回答所需字段在该条目中确实为空时，才明确说明对应缺失。不得把外部书目元数据未核验等同于“知识库没有来源”，也不得补造书名、版本、条文号、出处、参数或结果。

## 5. 证据标准与状态定义

每条审计结论必须附证据类型和定位：

- `CODE`：文件路径、函数/类名、行号或稳定代码定位；
- `TEST`：测试文件、测试名称、断言覆盖的输入与输出；
- `TRACE`：真实设备/运行环境的 trace ID、场景编号、关键日志片段和设备/版本信息。

证据优先级不是互相替代关系：CODE 证明实现路径存在；TEST 证明自动化条件下行为；TRACE 证明指定设备和场景真实运行。测试通过不能替代真机 TRACE，静态代码不能替代运行结果。

能力状态统一为：
- `IMPLEMENTED`：CODE + 对应 TEST + Find N2 真机完整 TRACE 均通过，且无未解释断点；
- `PARTIAL`：至少有可验证实现，但调用链某一环未通过、未覆盖或证据不完整；必须写明断点；
- `MISSING`：已检查目标调用链，确认不存在该能力；
- `UNKNOWN`：没有足够证据判断，或设备/日志/源码不可得。

禁止仅凭注册表项、页面入口、提示词、测试文件存在或模型回复通顺标记 IMPLEMENTED。无法取得 Find N2 时，相关项目保持 UNKNOWN/PARTIAL，不得推定通过。

## 6. 动态 TRACE 规范

### 6.1 必须覆盖的节点

每个场景以同一 `trace_id` 关联以下节点；不适用的节点显式记录 `NOT_APPLICABLE`，不能静默缺失：

`input → redflag → route(L0/L1/L2) → entity_resolution → retrieval → context_assembly → model_input/output → tool_parse → argument_validation → business_execution/result → result_validation → final_render → persisted_state`

至少记录：
- 场景编号、trace_id、时间戳、App commit/version、设备型号、Android 版本、模型文件版本、实际 GPU/CPU backend；
- 路由层级、命中规则/候选工具、实体 ID/类型/解析状态；
- 检索 query、命中/未命中条数、source ID、来源状态、被裁剪条目；
- 注入模型的各段来源、字符数、可用 token 数、截断标记；测试环境可保存完整 prompt，真机默认不保存敏感正文；
- 模型原始输出的结构化解析状态、耗时、异常类型；工具参数校验结果、业务函数签名/执行结果状态；
- 最终展示内容与来源引用的一致性、会话持久化和跨轮状态恢复结果。

### 6.2 隐私与日志安全

- TRACE 默认关闭；通过显式 Debug/审计开关启用，不得默认向正式用户持续记录对话正文。
- 健康症状、出生信息、图片、音频、个人身份信息不得写入普通持久化日志。默认只记录脱敏摘要、长度、字段状态和不可逆关联 ID。
- 如测试确需保留原文，必须由测试人员明确授权，限定本地受控环境、用途和保留期限；不得上传公共 CI 日志或仓库。
- 不记录模型文件、密钥、数据库内容或完整个人会话快照。
- TRACE 关闭时不得改变业务结果、执行顺序或安全门禁；日志写入失败不得阻断用户业务。

### 6.3 运行判定

一条场景 TRACE 必须能从输入关联到最终展示；关键节点缺失即不能判定完整通过。业务调用状态要区分 `NOT_STARTED`、`SUCCEEDED`、`FAILED`、`UNKNOWN`；执行结果未知时禁止自动重放有副作用的操作。

## 7. 场景验收集

每种模式至少 3 条场景，且至少 1 条负向；另加跨轮场景。每条必须记录预期实体/工具、参数、来源、是否调用模型、结果、耗时和失败分类。

| ID | 模式 | 输入/场景 | 必须验证的事实 |
|---|---|---|---|
| L-01 | 学习 | 比较桂枝汤与麻黄汤并引用原文 | 两个方剂实体分别解析；两方资料均进入上下文；引用与本地原文逐字/定位一致 |
| L-02 | 学习 | 上轮比较两方后追问“那它们的禁忌呢” | 指代回指上一轮两个实体；检索 query/结果覆盖两方；不得只靠模型记忆冒充本地资料 |
| L-03 | 学习负向 | 要求引用一条本地库不存在的古籍原文 | 明确说明当前知识库未检索到对应条目；不借助模型记忆补造书名、版本、条号或原文 |
| C-01 | 问诊演练 | “怕冷、发热、头痛”等自由描述 | 保留原话；AI 解释汗出、口渴、恶风等补问理由；未知字段不静默补齐；病例信息确认后进入现有规则问诊 |

| T-01 | 工具学习 | “比较桂枝汤原方用量与后世折算口径” | 可按现有确定性换算工具和有来源资料完成非个体化学习比较；参数、单位、算法和来源明确；不得把资料用量转换为对现实个人的服用指令 |
| T-02 | 工具 | 请求执行一个已登记计算工具并缺少必填参数 | 识别具体工具；列出缺失参数并追问；不得打开页面后假称已执行 |

| X-01 | 跨轮 | 第 3 轮回指第 1 轮的实体或业务结果 | 从持久化任务/消息上下文恢复准确实体与结果；不丢失、不串会话、不把助手话当用户事实 |
| X-02 | 跨轮负向 | 会话恢复后引用另一个会话的个人信息 | 会话隔离；不跨会话取值；无法确认归属时拒绝使用 |
| X-03 | 多轮稳定性 | 连续至少 5 轮文字对话，包含一次上下文检索和一次恢复/异常路径 | 无 state:7、无空回复假成功、无上下文静默丢失；失败状态可见；恢复后 transcript 一致 |

## 9. 执行阶段与交付物

### P0：多轮稳定性与安全门禁（并行启动）

3. 区分请求未执行、执行状态未知、执行成功但响应丢失；未知状态禁止盲目重放。
4. 红旗检查必须在模型调用之前确定性执行，并有负向测试。
5. 增加对应 Kotlin/Flutter 自动化回归；Find N2 连续多轮实测单独验收。

### P1：静态调用链与失败基线审计（不改业务行为）

交付 `docs/ai-capability-audit-report.md`（本约束文件 `docs/ai-capability-audit.md` 不得被审计报告覆盖），至少包含：
- 五种模式的提示词、工具、检索源、模型调用与结构化输出；
- 输入到最终展示的逐跳文件/函数调用链；
- ToolRouter 每个工具的页面入口/独立业务函数分类及函数签名；带 `BuildContext` 的入口不算 Headless；
- Prompt 注入内容、字符/token 预算、截断策略；
- 实体名称到 ID 的解析、别名表与缺口；
- 现有业务能力尚未向 AI 暴露的清单；
- 每项结论 CODE/TEST/TRACE 证据，缺证据标 UNKNOWN；

### P2：审计 TRACE 能力

- 增加默认关闭的审计日志开关和 trace_id 贯穿机制；
- 覆盖第 6 节关键节点，完成脱敏和日志隔离测试；
- 证明关闭 TRACE 时业务行为不变，打开时日志可关联完整调用链；
- 不允许为审计改造顺手重写业务路由或提示词。

### P3：Find N2 场景集实测与失败归因

- 按第 7 节逐项执行；设备不可用的场景标 UNKNOWN，不得以模拟测试替代真机结果。
- 每个失败记录断点、失败分类、证据和复测结果。
- 形成按真实失败数量排序的分类分布；先修主因类别，再扩展能力。

### P4：按证据最小化修复

- 检索失败：先修查询拆分、实体/别名映射、召回与排序，不先建 Agent。
- 上下文失败：修预算、分段、来源完整性、跨轮实体与引用传递。
- 理解失败：在 L0 确定性筛选后，用 E4B 做受约束选择/槽位填充和缺参澄清。
- 执行失败：抽取最小 Headless 业务函数适配器，要求无 Widget/BuildContext 依赖，定义 typed args/result、校验、错误与取消语义。
- 模型上限：缩小任务、拆成线性步骤、给出模板或明确限制；不得以编造结果掩盖上限。

### P5：统一结果协议与综合解释

仅在前述失败证据支持时实施。结果至少包含：能力 ID、输入参数、执行状态、结构化数据、单位、source IDs、来源类型、缺失字段、错误状态。AI 只能基于通过校验的结果解释；最终展示保留来源和不确定项。

### 14.2 模拟问诊免责声明与简单急重症提醒

### 14.3 数据保护分层

先完成低成本、可验证的保护：
1. Android 旧版和新版备份配置同时核对：`fullBackupContent`、`dataExtractionRules`、`allowBackup` 及实际 manifest 合并结果；不能只 grep 单个源文件就宣称备份已关闭。
2. 提供明确的“清除全部 AI 数据”入口；定义会话、消息、问诊任务/快照、附件原件、转写文本、缩略图、临时文件和模型交互缓存的删除范围。
3. 核实附件缓存的实际目录、生命周期、数据库引用和孤儿文件清理；清除后重启 App 再验证数据不可恢复。
4. 记录数据保留策略、清除确认、失败回滚/部分失败提示和删除测试。

SQLCipher 或其他数据库静态加密不属于上述低成本改造，必须独立评估性能、迁移、密钥管理、备份兼容和恢复风险后再决策。不得在没有密钥恢复方案时直接加密现有 SQLite 数据库。

### 14.4 检索与业务适配器的行为保持

在任何检索重构前，建立至少一组可重复黄金用例，并保存当前真实输出、召回条目 ID、排序、App 内知识库条目定位和上下文片段。首个黄金用例：

- 输入：查询“桂枝汤组成”，并查找《伤寒论》对应条文；
- 记录：当前检索 query、命中结果、排序、稳定 sourceId、App 内可打开的资产/章节/记录定位、上下文注入内容和最终展示；
- 验收：抽取适配器前后输出对比；任何召回、排序、来源或回答变化必须明确说明原因并由回归测试覆盖。

先测现有内存经典检索的召回与排序，不预设引入 FTS5。只有在黄金集证明当前方案存在可复现缺陷，并且对比实验显示改进后，才可单独立项引入 FTS5。

### 14.5 Capability 契约

必须区分以下概念，不得混用：
- **Page Tool**：注册表中的页面入口/Widget builder，只能证明 App 能导航到页面。
- **Headless Capability**：可在无 Widget、无 BuildContext 条件下独立调用的业务函数，具有明确输入 schema、输出 schema、参数校验、权限边界、取消/超时语义和错误状态。
- **Executed Capability**：本轮确实执行了 Headless Capability，并将经过验证的结构化结果回传当前会话。

只有同时具备执行契约和真实调用链证据，才可称为 AI 能调用业务能力。页面已打开、提示词列出工具名或模型说“已计算”均不构成执行证据。

### 14.6 P0 多轮故障审计必答项

只读审计报告 `docs/local-ai-multiturn-audit.md` 必须逐项回答并附源码行号；不能确认的写 `UNKNOWN`：

1. Engine、Conversation 的创建、初始化、释放、重建状态迁移图；列出 null、半初始化和引用已失效的状态。
2. 每条 GPU/CPU fallback、空回复重试、异常重建路径的触发条件、旧引用清空时机、资源释放顺序、历史回放内容及二次失败异常。
3. `state:7` 与“模型没有返回有效文本”的实际产生路径；没有设备日志时，根因结论必须为 UNKNOWN。
4. 并发发送、重入、用户取消、Dart Future 超时、Native 仍在执行、Activity 销毁、Engine 释放后 Conversation 复用的行为。
5. 恢复后模型内部上下文、SQLite transcript、UI 消息列表三者是否一致；上下文丢失时 Dart 是否收到明确状态。
6. 已有自动化测试逐项覆盖的状态与缺口。
7. 最小修复方案、需要新增的埋点、回归测试和风险排序。

另须检查消息持久化时序（仅 user 消息落库而 assistant 未完成、重复发送是否产生重复轮次），并区分“请求未执行 / 执行状态未知 / 执行成功但响应丢失”。Dart 超时或 UI 取消不等于 Native 推理已停止；执行状态未知时不得自动重放。

Engine 与 Conversation 生命周期必须分别建模；不得用单一 isReady 布尔值代表两者均可用。至少明确 Engine 状态、Conversation 状态、历史是否完成回放三个独立事实。

## 15. 2026-11-15 用户确认的知识来源验收口径

- 一般知识问答、经典文本和医案解读均以 App 实际知识库条目为唯一可引用对象；回答附稳定 `sourceId`，并能点击/按备注定位到对应本地资产、章节或记录。不得仅输出无法回查的裸书名或模型记忆中的出处。
- 不把纸本底本、版本、卷页或原始影像核对作为一般学习知识问答的前置条件，也不继续开展 83 条讲稿逐册逐页考证。
- 知识库已有且可定位时，不得因外部书目元数据缺失向用户显示“来源 MISSING”。`MISSING` 只表示实际本地资料缺项、检索未命中/失败、sourceId 无法解析/打开或所需字段为空。
- 如果知识库没有对应内容，明确告知“当前知识库未检索到对应条目”，不使用模型预训练记忆补齐成看似有来源的医学事实。
- 不重复审核已完成医学审核的知识库内容；知识来源定位、红旗输入安全 detector 和临床业务规则属于不同边界，不能互相替代。


## 16. 2026-11-15 用户最终确认：中医学习软件与模拟问诊定位

本节是当前产品定位的最终约束，覆盖并取代 §14 及历史审计记录中把问诊模块按临床分诊系统建设的要求。

### 16.1 产品用途

- 产品定位是**中医诊疗全过程辅助学习软件**，完整覆盖问诊、辨病、辨证、病机、治法、方剂、针灸、经典依据和医案复盘。
- 问诊助手是模拟辨证演练：用户可输入自身体验、书籍案例、经典医案或假设病例，AI 引导补问并解释推导；App 原有规则生成确定性问诊与辨证结果。
- 不得把“模拟学习”缩减为只提问、只显示辨证结论或不讲治疗方案。模拟病例必须可以继续学习治法、方剂配伍和针灸思路。
- 模拟分析不等于对用户或他人现实疾病的诊断，也不提供要求现实个人照做的治疗指令。

### 16.2 用户可见免责声明

以下内容固定展示在问诊学习流程中，覆盖问诊开始、问题进行中和结果解释阶段：

> 本问诊用于中医诊疗全过程的模拟学习与病例推演。所示辨病、辨证、病机、治法、方剂及针灸内容均为学习分析，不构成对现实个人的医疗诊断或治疗指令。若你或他人有现实身体不适，请及时就医；请勿仅依据模拟结果自行诊断、用药、停药或实施治疗。如出现胸痛、明显呼吸困难、意识不清、抽搐或大量出血等急重症表现，请立即拨打 120 或前往急诊。

- 该提示采用固定文案，不交给模型自由改写。
- 允许在界面上使用简洁提醒条；不弹出多层医疗风险问卷，不要求用户在每一轮重复确认免责声明。
- 免责声明应在键盘弹出和对话滚动时仍能看见。



### 16.3 简单急重症提醒边界

- 急重症提醒是一般性就医提示，不判断病情轻重、不进行临床分级、不推断疾病、不推荐急救操作。
- 不建立五类临床 detector、复杂语义分类、医师签字工作流、YAML 规则库或 50 条临床黄金集作为模拟学习功能门槛。
- 不因缺少医学 detector、医学审核版本或临床覆盖率而阻断用户使用模拟学习流程。
- 若用户明确描述现实身体不适，回复应提醒及时就医；若描述明显急重症表现，提示立即拨打 120 或前往急诊。除此之外按学习问题解释，避免个人医疗判断。

### 16.4 不变的 AI / App 分工

- AI 负责理解用户的学习意图、保留与整理自然语言、引导补问、解释提问理由、串讲知识并归纳规则结果。
- App 负责原有确定性问诊题目、选项、规则执行和结果生成；AI 不得篡改规则或虚构结果。
- AI 可在规则结果基础上完整解释模拟病例的辨病、辨证、病机、治法、方剂配伍和针灸思路；输出明确标为“模拟病例分析/学习结果”，不得称为用户本人的现实诊断。
- 学习助手复用现有 `AssistantKnowledgeContextBuilder`，使用方剂库、古籍索引、倪师医案及现有针灸/穴位资料；关键内容通过稳定 sourceId 跳转 App 原详情页。
- 知识库已审核内容不重复审核；回答按现有 sourceId 定位即可，不追加古籍纸本版本/卷页考据。

### 16.5 工程验收范围

验收必须覆盖：免责声明与急重症提示正确且持续可见；引导补问和理由解释；既有规则结果真实性；模拟病例的辨病辨证、病机、治法、方剂和针灸教学；经典/医案 sourceId 与详情页跳转；无医学 detector 时模拟学习仍能执行；模拟方案不会被转化为现实个人诊疗指令。

不再将临床红旗 detector、医学词表、语义召回率、医学责任签字或 SaMD 级验证列为本学习软件的云端工程待办。
