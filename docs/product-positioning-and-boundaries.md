# 产品定位与开发边界：中医诊疗全过程学习

> **文件性质：产品级规范 / 开发准则。** 本文件是产品定位、AI 助手职责、学习输出范围和现实医疗边界的权威依据。后续产品设计、提示词、代码、测试、文案和验收均须遵守。
>
> **适用范围：** 全 App 中医学习能力，重点约束“问诊助手（模拟辨证演练）”与“学习助手（经典、方剂、针灸、医案串讲）”。
>
> **优先级：** 本文件优先于旧审计记录、历史台账和旧提示词中将问诊缩减为“只演示辨证、不教诊断或治疗”的表述。历史记录可以保留作决策轨迹，但不得继续作为当前产品要求。

## 1. 产品定位

本软件是**中医诊疗全过程辅助学习软件**。目标不是只让用户记住中医概念，也不是只展示一个辨证结论，而是帮助用户逐步理解和练习完整的中医诊疗思路：

**四诊问诊 → 信息整理与补问 → 辨病 → 辨证 → 病机分析 → 治法确定 → 方剂与药物配伍 → 针灸取穴思路 → 经典依据 → 医案对照与复盘。**

学习中医当然包括学习诊断疾病、辨别证候和研究如何治疗。产品不得因为“模拟学习”而删掉诊断教学、治法教学、方剂教学或针灸教学。

产品所教的是完整诊疗知识与推理方法；模拟病例所得结论和方案属于**学习分析**，不自动转化为对现实个人的诊断或治疗指令。

## 2. 两个核心助手

### 2.1 问诊助手：模拟辨证演练

**目标：通过 AI 引导用户思考，完成从问诊到治疗思路的病例演练。**

用户可以输入一段症状描述，来源可以是：
- 用户自己的身体体验；
- 书籍、经典或历史医案中的病例；
- 用户自行编写的假设病例。

无论输入来源如何，问诊助手都按学习演练处理，不擅自把用户的描述认定为已经确认的现实疾病。

**标准交互过程：**

1. **理解原始描述**：保留用户原话，整理症状候选项，不丢失原始语境。
2. **引导补充问诊**：指出当前缺少哪些信息，并解释为什么要问。例如用户提到“怕冷、发热”，AI 可以追问“有汗还是无汗”“口渴不渴”“是否恶风”等，并说明这些信息如何帮助鉴别表虚、表实等思路。
3. **确认关键信息**：候选症状或选项需按现有问诊流程确认；不确定的信息标记为未知，不得自行补齐。
4. **执行既有辨证**：由 App 原有问诊控制器和确定性规则执行题目、选项、辨证与结果生成。AI 不篡改规则、不虚构规则输出。
5. **讲清推导逻辑**：说明哪些信息支持或不支持某一辨病、辨证方向，哪些信息仍不足；区分规则结果、经典依据和 AI 的解释。
6. **完成治疗教学**：针对当前模拟病例，继续讲解病机、治法、相关方剂及其组成配伍思路、针灸选穴思路和适用依据。不得在辨证结论后戛然而止。
7. **引用与复盘**：关联《伤寒论》等经典条文、方剂资料和医案；说明症状或关键问诊答案变化时，推导与治法可能如何变化。

**示例：**

用户输入“怕冷、发热、头痛”。AI 不应只返回一个证名，也不应直接跳到结论。它应先引导追问汗、口渴、恶风等信息；在信息确认并由现有规则完成模拟辨证后，解释结果为何指向相应的六经或证候，关联经典条文，再继续讲解相应治法、代表方和针灸思路。资料不足时明确指出不足，不伪造条文、规则结果或方剂依据。

**问诊助手必须覆盖的学习环节：**

- 问什么、为什么问，以及答案如何影响鉴别；
- 辨病与辨证的区别及其推导依据；
- 病机分析及证据链；
- 治法如何从辨证结果推导；
- 方剂选择、组成、配伍关系及其与证候的对应；
- 针灸取穴、配穴思路及其理论依据；
- 经典条文和医案如何支持、补充或形成鉴别；
- 对信息变化进行反事实比较和病例复盘。

### 2.2 学习助手：经典、方剂、针灸、医案串讲

**目标：把 App 现有知识资料串联起来讲清楚，而不只是返回零散搜索结果。**

必须优先复用现有 `AssistantKnowledgeContextBuilder` 及其检索、上下文、来源定位和详情跳转链路。当前重点知识来源包括：

- 方剂库：方剂组成、药物角色、配伍关系、相关治法及适用证候；
- 古籍索引与经典条文：原文、条文定位、关键词及辨证依据；
- 倪师医案：病例表现、问诊线索、辨证过程、治法和用方；
- 针灸及穴位资料：穴位信息、选穴和配穴思路及其来源。

**讲解应形成关联链条：**

`病例/问题 → 经典条文 → 辨病辨证 → 病机 → 治法 → 方剂配伍 / 针灸选穴 → 相关医案`

具体要求：

1. 结合用户的问题组织资料，不机械堆叠检索片段。
2. 讲清楚条文、症状、证候、病机、治法、方剂和针灸之间的关系。
3. 明确区分原文、知识库事实、既有规则结果和 AI 的综合解释。
4. 每条可追溯资料使用稳定 `sourceId`，并提供点击进入 App 原详情页的入口。
5. 资料未命中、来源 ID 无法解析或条目本身缺字段时，明确标注缺失，不用模型记忆补造原文、条号、药物组成或医案细节。
6. 不另建平行知识库、重复检索器或第二套上下文构造系统；只有现有 builder 确有可复现缺口时，才按最小改动修复。

## 3. AI 与 App 的职责分工

| 环节 | 主要责任 | 边界 |
|---|---|---|
| 自然语言理解 | AI | 理解用户描述、学习意图、症状表达和指代；保留原话 |
| 引导式问诊 | AI + 现有问诊流程 | 提示缺项、解释提问理由；不擅自确认未知信息 |
| 规则问诊与辨证 | App 确定性代码 | 现有题目、选项、控制器和规则引擎负责实际执行与结果生成 |
| 病机、治法与治疗知识讲解 | AI + 已检索知识 | 可完整讲解模拟病例的辨证推理、治法、方剂和针灸方案；依据必须可追溯 |
| 知识检索与来源定位 | 现有知识库和 `AssistantKnowledgeContextBuilder` | 复用已有资源、sourceId 和详情页跳转 |
| 计算及结构化业务结果 | App 确定性代码 | 模型不得心算伪造结果，也不得覆盖 App 返回值 |
| 综合讲解与复盘 | AI | 在已提供资料和已校验结果范围内解释、比较、归纳；标记推断与不确定性 |

原则：**AI 负责理解、引导和讲解；App 原有确定性模块负责规则、计算和业务事实。** 不因引入 AI 而迁移或重写既有辨证规则。

## 4. 模拟学习与现实医疗的边界

边界不是“不能教诊断和治疗”，而是区分**对模拟病例进行完整诊疗教学**与**替现实中的个人作医疗决定**。

### 4.1 允许并且应该提供的学习内容

对于模拟病例，包括以用户自身体验作为演练素材的输入，产品可以：

- 分析病例信息，讲解辨病和辨证的候选方向及依据；
- 说明当前证据的支持点、矛盾点和缺失项；
- 讲解病机、治法及其推导过程；
- 针对该模拟病例讲解治疗方案，包括代表方、方剂组成、配伍关系、加减思路，以及针灸选穴和配穴思路；
- 讲解经典原文、方剂资料和医案依据；
- 对照不同假设、补充症状或改变问诊答案，比较辨证与治法的变化；
- 在本地资料确实包含相关内容时，呈现原方组成、历史用量或资料中记录的用法，并明确其资料来源和语境。

不得把“模拟学习”解释为禁止出现疾病名称、证候结论、治法、方剂或针灸方案。不得把教学内容缩减为只问问题、只展示辨证过程或只讲理论而不讲治疗。

### 4.2 不得越过的现实应用边界

- 不把模拟推导表述成“你已经患有某种疾病”或对他人的现实诊断。
- 不将模拟病例的方案转化为“你本人现在应该服用某方、按某剂量服用、停用或调整某药”等现实个人治疗指令。
- 不要求用户根据模拟结果自行诊断、用药、停药或实施治疗；现实身体不适应及时寻求合格医疗服务。
- 不得将缺失资料、模型推断或未经执行的规则结果伪装成确定结论。
- 不得因用户输入来自本人体验，就自动将学习演练升级成临床诊疗流程；也不得因输入提到症状，就建立复杂临床分类器或把正常学习流程全部阻断。

### 4.3 固定免责声明与急重症提醒

问诊开始、进行中和结果解释阶段均固定展示下列文案；不得交由模型临场自由改写：

> 本问诊用于中医诊疗全过程的模拟学习与病例推演。所示辨病、辨证、病机、治法、方剂及针灸内容均为学习分析，不构成对现实个人的医疗诊断或治疗指令。若你或他人有现实身体不适，请及时就医；请勿仅依据模拟结果自行诊断、用药、停药或实施治疗。如出现胸痛、明显呼吸困难、意识不清、抽搐或大量出血等急重症表现，请立即拨打 120 或前往急诊。

急重症提醒仅是一般性、简明的求助提示：
- 不判断病情轻重，不进行临床分级或分诊；
- 不推断用户患有什么疾病；
- 不提供急救操作步骤；
- 不建设五类临床红旗规则库、复杂语义分类器、YAML 医学规则系统、临床召回率指标或医师签字流程作为模拟学习功能的准入条件；
- 不因缺少上述 detector、审核或覆盖率证明而阻断模拟学习。

固定提示在 UI 中应持续可见，不能被对话滚动或键盘弹出遮挡。

## 5. 知识来源和内容可信度

- 经典、方剂、针灸和医案讲解优先基于 App 已有知识库。
- 资料引用必须关联稳定 `sourceId`，并能打开对应 App 内详情页。
- `原文/知识库条目`、`确定性规则结果`、`App 数据` 与 `AI 归纳` 必须明确区分。
- 不能因为外部纸本版本、卷页或影印本坐标尚未考证，就把 App 内已有且可定位的知识条目判为来源缺失。
- 已完成医学审核的知识库内容不重复审核；本准则要求的是调用、引用和讲解链路可靠，不是重新审核整个知识库。
- 本地资料没有对应内容时标记 `MISSING`；检索、解析或详情跳转状态无法确认时标记 `UNKNOWN`。不得靠模型预训练记忆补造来源。

## 6. 产品验收准则

后续设计评审、代码审查和测试至少检查以下事项：

| 验收项 | PASS 条件 | REJECT 条件 |
|---|---|---|
| 完整诊疗学习链 | 从问诊、辨病辨证、病机、治法，到方剂和针灸思路均有对应学习设计 | 只收集症状或只展示辨证结论，刻意不教治法与治疗方案 |
| 引导式问诊 | AI 能解释为什么追问、哪些信息缺失、答案如何影响鉴别 | 无理由连续提问，或擅自补齐未知信息 |
| 规则可信 | 辨证结果由现有确定性规则生成，AI 不覆盖或伪造 | AI 自行编造规则结论或修改既有业务规则 |
| 治疗教学 | 能针对模拟病例讲清治法、代表方/配伍及针灸思路和依据 | 将所有方剂、针灸和治疗方案内容一律视为禁止输出 |
| 知识串讲 | 复用 `AssistantKnowledgeContextBuilder`，把经典、方剂、针灸和医案关联解释 | 只堆检索片段，或另建重复知识检索体系 |
| 来源与跳转 | 关键资料带稳定 sourceId，能跳转 App 原详情页 | 无来源却伪称经典原文，或链接到错误条目 |
| 现实医疗边界 | 模拟结果标为学习分析，不转成现实个人诊断或治疗指令；固定提醒可见 | 声称已诊断用户现实疾病，或要求用户按模拟结果自行用药/停药/治疗 |
| 安全范围 | 保留简明急重症求助提示，不建设临床分诊体系阻断学习 | 以临床 detector、医师签字、临床召回率为学习功能准入门槛 |
| 既有能力复用 | 复用现有问诊控制器、规则引擎、知识库和详情页入口 | 无失败证据就重写规则、复制知识库或另起 Agent/检索架构 |

## 7. 对后续开发任务的约束

1. 新增或修改问诊助手能力时，按“引导问诊 → 规则辨证 → 结果解释 → 治法/方剂/针灸教学 → 经典与医案引用 → 复盘”检查完整性。
2. 新增或修改学习助手能力时，先核查并复用 `AssistantKnowledgeContextBuilder` 的真实输入、检索结果、来源字段和详情跳转；不得先设计第二套检索系统。
3. 保留原有 `TcmInterviewConversationController`、`DiagnosticEngine`、`DiagnosticRules` 及相关业务规则。AI 只能理解和解释，不能覆盖其确定性输出。
4. 任何新内容均须区分来源事实与 AI 归纳；资料不足时标记缺失，不得虚构条文、方剂、穴位、医案或诊疗结果。
5. 不把“规范已写入”当成功能已完成。每项能力仍须以代码、针对性测试和实际运行证据分别验收；未实现或未验证的部分如实标记。
6. 修改产品定位或现实医疗边界，必须更新本文件，并同步更新 `docs/ai-capability-audit.md` 与 `docs/ai-modernization-execution-ledger.md`，避免多份规范漂移。

---

**最终原则：完整教会用户中医诊疗思维——不仅要会问、会辨，还要理解病机、治法以及方剂和针灸的治疗思路；同时明确模拟病例学习不等于对现实个人作出医疗诊断或治疗指令。**
